# Кеп композера: JS, а не чистый CSS

Контракт — [спека composer-viewport-cap](../specs/composer-viewport-cap.md).

## Контекст

Окно ввода BB (`[data-app-composer]`; в 0.49 — div, `<form>` в разметке нет) разрасталось до ~половины рабочей области, а на мобильном могло перекрывать почти весь экран: штатный потолок 312px стоит только на скролл-зоне редактора, а вложения, очередь и тулбар добавляют высоту сверх него. Владелец требует ≤ 1/3 рабочей области для всего блока.

## Решения

1. **Дом фичи — `bb-plugin-compact-ui`** (до переименования — `bb-plugin-sidebar-collapse`, `7f8041b`). Это наш плагин space-оптимизаций (свёртка списков, скрытие rail, компактные хедеры); новый плагин под одно CSS-правило не создаём.
2. **Кеп считает JS-контент-скрипт `composer-cap`, а не CSS.** Чистый CSS (`max-height` на форме) не может честно ограничить блок с переменным содержимым: дети формы — это сворачиваемый grid-контейнер с `overflow:hidden`, жёсткий кап обрезал бы тулбар и вложения. JS измеряет реальную высоту формы и прижимает именно скролл-зону редактора.
3. **Рабочая область = innerHeight − 96px** (page header + status bar): «1/3 рабочей области», а не «1/3 абсолютной высоты экрана» — первая итерация с `33svh` дала владельцу те же ~50/50, потому что вложения остались некепленными.
4. **Стабильная формула без гистерезисных флагов**: кеп держится, пока `natural = formH − editorH + min(scrollHeight, 312) > cap`. `scrollHeight` отражает контент даже в обрезанном состоянии — цикл «снял → выросло → надел» исключён конструктивно.
5. **`!important` убран из CSS-фолбэка**: первый вариант правила перебивал inline-стиль JS и делал кеп нерабочим. Якорь — `[data-app-composer]` (стабильный data-атрибут; `group/promptbox` остался только в CSS-классах, на элементе его нет); inline JS приоритетнее таблицы стилей.
6. **Очередь сообщений — второй поглотитель, отвязанный от редактора.** Развёрнутая панель показывает ровно min(N,3) строки и клампится измеренной высотой, а не по событию переполнения кепа: живая диагностика показала, что `div.overflow-y-auto:has(.ProseMirror)` в 0.49 внутри карточки отсутствует, и вся логика очереди годами была мёртвым кодом за `if (!scroll) return`. Скролл редактора теперь определяется по computed `overflow-y` вверх от `.ProseMirror`.
7. **Панель растят предки по формуле «цель ребёнка + слак», а не дельтой.** Скролл очереди — `flex-1` внутри хост-бюджетированной секции: `max-height` на нём только обрезал контент. Каждому предку до карточки выставляется `min-height` = нужная высота ребёнка + его слак на прочих детей; значения снимаются каждый проход — первая версия с «текущая + дельта» на каждом уровне двоила рост и оставляла мёртвый зазор под панелью.
8. **Урок жизненного цикла**: `bb plugin reload` диспозитит content scripts без перемонтажа — новые поднимаются только при полной загрузке страницы. Проверка «код доехал до экрана» — маркер `data-cap-mounted` в DOM через content script, а не факт install/reload.
9. **Fail-open**: без `ResizeObserver` (jsdom) монтирование деградирует молча; незнакомая разметка не трогается.

## Последствия

- Кеп применяется к любому `group/promptbox` в документе, включая будущие варианты композера с той же разметкой — MutationObserver подхватывает новые формы.
- Плагин теперь запускает два наблюдателя (Mutation + Resize) на всё время сессии; нагрузка константная, enforce вызывается только при изменении размеров/DOM.
- Если BB сменит `[data-app-composer]`/`[data-queued-messages-scroll]` или уберёт скроллящийся предок у редактора — кеп молча отключается (fail-open), нужна новая ревизия селекторов. Так случилось уже дважды: исчезновение `<form>` в 0.49 и смена обёртки редактора — оба раза код дох молча, поэтому добавлен DOM-маркер живости.
