# ADR-0018. Live Call: быстрое «да» по часам браузера, короткий вопрос, сначала вызов

## Контекст

Звонок владельца 09.11, 00:34–00:40 UTC:

- **Владелец сказал «да» четыре раза, засчиталось третье.**
  - Первое отклонено как раннее, хотя прозвучало после начала вопроса.
  - Второе пропало без следа.
  - Третье прошло только после 10-секундного вопроса.
  - Четвёртое — ответ на лишний переспрос после «выполнено».
- **Модель сказала «секунду, уточню» и 70 с ничего не делала.**
- **Gemini прислал два вызова `brain_ask` подряд**, на экране две карточки.

Причины:

- **Момент реплики владельца сервер угадывает.**
  - Берёт первый кусок транскрипта и вычитает 2 с.
  - По ADR-0012 п. 3 момент должен браться по детектору речи. Но браузер его не передаёт, поэтому в коде всегда работает запасная оценка.
  - Начало вопроса считается отдельной оценкой, по байтам звука. Сравниваются две неточные оценки.
- **Флаг раннего «да» глушит следующие реплики.**
- **Модель читает свой вариант вопроса**, а не короткий `say` от сервера.
- **Итог подтверждения ждёт тишины.** Модель успевает переспросить.
- **Промпт велит говорить «секунду…» до вызова инструмента.** Gemini иногда закрывает ход без вызова: по последним 40 звонкам — в 3 из ~15 обещаний.

## Решение

Подробности — спека §7.2.

1. **Перебивание по звуку, который владелец реально услышал (пересмотр 09.11, решение владельца — упрощение).** После шести кругов ревью, где каждое уточнение места вопроса по транскрипту открывало новый путь ложного или мёртвого «да», место вопроса внутри хода для решения больше не определяется. «Да» засчитывается, если браузер уже проиграл звук модели, полученный после запроса подтверждения (`speech_start { turnSeq, playedMs }` против хода и объёма звука на момент запроса). Принятый риск: «да» во время фразы ожидания до слов вопроса засчитывается; полный текст действия — на карточке. Без кадра — только окно или кнопка. Ниже — первоначальный вариант, заменённый этим пунктом:
   - Браузер шлёт `speech_start { turnSeq, playedMs }`: сколько звука хода модели он реально проиграл к началу речи владельца.
   - Сервер сравнивает это с позицией начала вопроса в том же ходе.
   - Обе величины меряются в одной системе отсчёта, синхронизация часов не нужна.
   - Без кадра остаётся прежняя оценка, и в журнал пишется `timing: estimate`.
2. **Правило «да до вопроса не засчитывается» остаётся.** Меняется только точность. Каждое отброшенное «да» пишется в журнал.
3. **Модель читает `say` дословно.** Длинный вопрос попадает в журнал как метрика (`question_long`).
4. **Итог подтверждения уходит модели сразу, с прерыванием её речи** (`INTERRUPT`).
5. **Сначала вызов инструмента, потом короткая фраза ожидания.** Инструменты `NON_BLOCKING`, модель может говорить, пока они работают.
6. **`brain_ask` — один вопрос за раз (single-flight).**
   - Совпадающий вопрос или его продолжение присоединяется к текущему.
   - Другой вопрос встаёт в очередь.
   - Сырые вызовы от Gemini пишутся в журнал.

## Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Засчитывать любое «да» после запроса, без привязки к звуку ответа | «Да» как хвост собственной просьбы или до того, как владелец услышал хоть что-то от модели. Привязка к реально проигранному звуку ответа сохраняется. |
| Определять начало вопроса внутри хода по транскрипту (первый вариант этого ADR) | Транскрипт Gemini не синхронен со звуком; шесть кругов ревью — каждый раз новый путь ложного или мёртвого «да». |
| Увеличить поправку 2 с или ослабить проверку раннего «да» | Задержка распознавания плавает. Ослабление открывает ложное подтверждение. |
| Серверный «пинок» модели, если она пообещала и не вызвала инструмент | Лечит симптом, причина — в промпте. Вернёмся, только если метрика после правки промпта не станет 0. |
| Склеивать дубли карточек на клиенте | Скрывает двойной вызов, но не убирает двойной ход в мозговом центре. |

## Последствия

- «Да» засчитывается через ~0,5 с после начала вопроса, ждать конца фразы не нужно.
- Новый клиентский кадр. Старый клиент (без `speech_start`) перебиванием не подтверждает: «да» — в окне после ответа или кнопкой.
- В журнале звонка появляются `tool_call`, `early_approval`, `question_long` и `timing` у вердикта: спорные случаи разбираются по логу.
- Приёмка: метрики «обещание без вызова = 0», «длинный вопрос = 0», «да через 0,5 с с первого раза — 10 из 10».
