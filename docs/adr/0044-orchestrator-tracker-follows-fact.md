# ADR-0044: Трекер следует за фактом (PLUG-403)

## Контекст

До 24.11 плагин orchestrator статусы задач трекера не менял: их ставили люди и агенты вручную. В результате около 30 задач PLUG висели в `in_review`/`in_progress`, хотя были выложены (PLUG-396, PLUG-361) или выполнены (PLUG-399). Наблюдатель-сверка (§32.5.4, ADR-0041) закрывает записи очереди по статусу трекера, поэтому неверный трекер делает отчёт готовности к `strict` ложным.

## Решение

1. Плагин сам ставит статус по машинным событиям: первая раздача исполнителю → `in_progress`, первая раздача ревью → `in_review`, `release published` → `done`, сданное исследование → `done` (orchestrator-graph §32.7).
2. Раз в час на проход `reconcile` задачи в `in_progress`/`in_review`, чей итог влит в основную ветку, закрываются с доказательством (`merged_sha` или id выкладки). Задачи без движения 72 ч — вопрос координатору, без автозакрытия.
3. Каждое изменение — событие `tracker.sync` с доказательством. Статусы, выставленные человеком (`done`/`canceled`), плагин не трогает и закрытое не переоткрывает.
4. Прошлое чинится разовой командой `reconcile --tracker` по слову координатора (PLUG-402 — ручная сверка 24.11), не автоматически при старте (урок 8).

## Последствия

- Трекер становится достоверным источником для §32.5 и для владельца.
- Ошибка автоматического закрытия возможна только при неверном `merged_sha`. Поэтому без доказательства статус не меняется, а `--dry-run` показывает изменения до записи.
