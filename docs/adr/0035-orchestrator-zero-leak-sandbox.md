# ADR-0035: Изоляция данных и исполнение в песочнице для публичных и бесплатных моделей (Zero-Leak Sandbox)

## Контекст

Использование бесплатных и публичных моделей (OpenCode free models, веб-интерфейсы Gemini/Argon, публичные пулы ACP-провайдеров) позволяет существенно сократить затраты на рутинные этапы разработки (написание спецификаций, первичный аудит, генерация тестов, вспомогательные исследования). Однако публичные модели несут критический риск утечки конфиденциальной информации: промпты, фрагменты кода и системные метаданные могут сохраняться на сторонних серверах и использоваться для дообучения.

Независимый аудит безопасности архитектуры изоляции данных (`audit-zero-leak-argon.md`, тред `thr_dsjymhnts5`) выявил 5 фундаментальных блокеров в наивном подходе «переменные окружения + фильтрация стартового промпта»:

1. **Утечки через устройство Git и историю коммитов:** стандартный механизм `git worktree` не изолирует базу объектов Git, а создаёт в рабочей папке файл `.git` со ссылкой `gitdir` на общий каталог `.git/worktrees/...` родительского репозитория. Если изолировать процесс строго в папке worktree, команды `git status` и `git diff` падают из-за потери доступа к `commondir`. Если же пробросить родительский `.git` внутрь песочницы, агент на публичном маршруте получает неограниченный доступ ко всей истории проекта (`git log -p --all`, `git reflog`, `git rev-list --objects`), удалённым из рабочего дерева секретам, конфиденциальным файлам через `git show HEAD:<confidentialPath>`, токенам из `.git/config` и именам/email разработчиков (`git log --format="%an %ae"`).
2. **Runtime bypass `confidentialPaths`:** проверка `confidentialPaths` только на стартовом диффе, описании задачи и `--attach` не защищает от чтения файлов во время работы агента. Исполнитель с инструментами `read_file` или `bash` может напрямую прочитать любые конфиденциальные модули из рабочего дерева, после чего их содержимое отправляется публичной модели в следующем же сообщении диалога.
3. **Кэши, артефакты сборки и симлинки:** очистка `process.env` не защищает от секретов, содержащихся в проектных файлах (`.npmrc`, `.yarnrc.yml`, `pip.conf`, `package-lock.json` с URL приватных реестров и токенами), дампов кэшей (`.pytest_cache`, `.mypy_cache`, `.next`, `node_modules/.cache`), а также атак через симлинки (`Symlink Traversal`, `ln -s /etc/passwd`), позволяющих читать файлы за пределами песочницы.
4. **Атака Unmasking Oracle и поломка синтаксиса заглушками:** использование кириллических скобочных масок вроде `[скрыто: secret]` или `[host-1]` ломает парсеры URL, JSON/YAML, синтаксис языков программирования и сходимость `git apply`. При слепой обратной замене токена секрета на реальное значение во всём выходном диффе злоумышленник через indirect prompt injection может заставить модель вставить токен секрета в публичный файл (README, лог ошибки), в результате чего оркестратор сам запекает секрет в репозиторий.
5. **Отсутствие гранулярности и риск автоматического даунгрейда:** бинарное деление на «доверенные» и «публичные» маршруты смешивает политику хранения данных (Data Retention) и уровень доступа к инструментам (Capability Trust). При сбоях или исчерпании квот доверенных провайдеров недопустим автоматический переход задачи на публичный маршрут.

## Решения (устранение 5 критических блокеров аудита)

### 1. Snapshot Sandbox вместо git worktree (Блокер 1)

Для любых исполнителей и процессов на публичных маршрутах (`route.trust = "public"`) **СТРОГО ЗАПРЕЩЕНО** использование живых рабочих деревьев `git worktree` и проброс родительской директории `.git`.

Оркестратор реализует изолированный механизм **Snapshot Sandbox**:
- Снимок рабочего состояния формируется через команду `git archive --format=tar <base-sha>` из проверенной ревизии репозитория и разворачивается в одноразовый временный каталог `/tmp/bb-sandbox-<sandboxId>`.
- Внутри каталога песочницы создаётся одноразовый локальный репозиторий: `git init`, настройка фиктивного авторства (`git config user.name "Sandbox Agent"`, `git config user.email "sandbox@localhost"`), и фиксируется единственный начальный коммит: `git add -A && git commit -m "sandbox root snapshot"`.
- Никаких ссылок на родительский репозиторий, `commondir`, `gitdir` или `.git/config` хоста не существует. Попытки выполнить `git log` или `git reflog` показывают ровно один коммит слепка задачи.
- По завершении работы агента оркестратор извлекает результат через `git diff HEAD` внутри песочницы, валидирует его через DLP-фильтр и переносит в виде чистого патча в рабочее дерево оркестратора. После переноса временный каталог `/tmp/bb-sandbox-<sandboxId>` немедленно и безопасно уничтожается.

### 2. Физическое исключение `confidentialPaths` из ФС песочницы (Блокер 2)

Правило `confidentialPaths` из политики оркестратора (§2.1) применяется как **правило физического формирования файловой системы песочницы**:
- При формировании слепка через `git archive` файлы и каталоги, соответствующие шаблонам `confidentialPaths`, принудительно исключаются из архива (через `--exclude` либо предварительный парсинг путей).
- На уровне виртуальной файловой системы песочницы точки монтирования конфиденциальных путей принудительно перекрываются пустыми read-only устройствами (`--ro-bind /dev/null /workspace/<path>`) либо изолированными пустыми директориями `tmpfs`.
- Любая попытка агента или запущенных им процессов (включая `bash`, `read_file`, тестовые раннеры) прочитать конфиденциальный файл завершается либо получением пустого содержимого, либо ошибкой `ENOENT`. Утечка содержимого в рантайме физически невозможна.

### 3. DLP Redaction Engine и защита от Unmasking Oracle (Блокер 3)

Кириллические скобочные маркеры полностью упраздняются. Все маски формируются в виде синтаксически валидных ASCII-идентификаторов, совместимых с парсерами JSON, YAML, URL и AST целевых языков программирования:

| Тип данных | Формат ASCII-замены | Обратимость (Unmasking) | Правило безопасности при сведении диффа |
|---|---|---|---|
| Сетевые имена и домены | `host-N.bb-mask.internal` | Двусторонняя (по словарю задачи) | Разрешена обратная подстановка в диффах и отчётах |
| IPv4-адреса | `198.51.100.N` (RFC 5737 TEST-NET-2) | Двусторонняя (по словарю задачи) | Сохраняет валидность IP/URL парсеров при прогоне тестов |
| ID тредов и задач | `thr_MASKED_NNN`, `TASK_MASKED_NNN` | Двусторонняя (по словарю задачи) | Безопасная подстановка при формировании отчётов |
| Секреты, ключи, токены (§22.1) | `__BB_REDACTED_SECRET_NNN__` | **Строго односторонняя** | **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНА** подстановка в добавленные (`+`) строки диффа и текст ответа |

**Защита от атаки Unmasking Oracle:**
1. Обратная подстановка токена секрета `__BB_REDACTED_SECRET_NNN__` разрешена **исключительно в неизменённых контекстных строках** unified diff (строки без маркера `+` в начале), что гарантирует успешную сходимость `git apply` на реальном репозитории.
2. Если токен секрета `__BB_REDACTED_SECRET_NNN__` обнаруживается в добавленной строке (`+`) диффа или в текстовом теле отчёта модели, сдача немедленно бракуется с отказом:
   `dlp-violation: обнаружена попытка эксфильтрации токена секрета в коде или отчёте`.
3. Сведение результата выполняется в два этапа:
   - Патч публичной модели применяется к маскированной копии файлов в памяти.
   - Выполняется контролируемый unmasking разрешённых идентификаторов хостов и IP, после чего по финальному диффу запускается вторичный DLP-сканер. При обнаружении любого неучтённого секрета коммит блокируется.

### 4. Легковесная песочница на базе bubblewrap (`bwrap`) + cgroups v2 (Блокер 4)

Оркестратор отказывается от ненадежных проверок путей в Node.js/Python в пользу изоляции на уровне пространства имён ядра Linux через утилиту `bubblewrap` (`bwrap`) с накладными расходами ~3–5 мс:

- **Пространства имён:** запуск с параметром `--unshare-all` (Mount, PID, Network, IPC, UTS, Cgroup).
- **Жизненный цикл:** обязательный флаг `--die-with-parent` — при падении, отмене или таймауте процесса оркестратора все дочерние процессы внутри песочницы гарантированно уничтожаются ядром ОС без образования зомби-процессов.
- **Изоляция ФС:**
  - Системные каталоги хоста (`/usr`, `/bin`, `/lib`, `/lib64`, `/etc/alternatives`) монтируются строго на чтение (`--ro-bind`).
  - Файловые системы `/tmp` и `/var/tmp` монтируются в оперативную память (`--tmpfs /tmp`).
  - Каталог `/proc` монтируется изолированно (`--proc /proc` в сочетании с `--unshare-pid`), скрывая процессы хоста и других агентов.
  - Слепок Snapshot Sandbox монтируется в фиксированный виртуальный путь `/workspace` (`--bind /tmp/bb-sandbox-<sandboxId> /workspace`), скрывая структуру каталогов хоста и реальное имя пользователя.
- **Сетевой карантин:** флаг `--unshare-net` изолирует сетевой стек, оставляя доступным только интерфейс `lo`. Прямой выход в интернет и локальную сеть хоста заблокирован. Взаимодействие с оркестратором осуществляется исключительно через стандартные потоки ввода-вывода (stdio) либо проброшенный локальный Unix-сокет.
- **Ограничение ресурсов (cgroups v2 и prlimit):**
  - Защита от fork-бомб: ограничение числа процессов (`RLIMIT_NPROC` = 64, cgroups `pids.max` = 64).
  - Лимиты по оперативной памяти (`RLIMIT_AS` / memory.max) и времени CPU.
  - Закрытие и изоляция системных сокетов (`SSH_AUTH_SOCK`, Docker socket, D-Bus).

### 5. Трехуровневая матрица доверия (Capability & Trust Matrix) и принцип Fail-Closed (Блокер 5)

Политика маршрутизации оркестратора разделяет доверие на три уровня (`route.trust`):

| Уровень `route.trust` | Примеры провайдеров | Режим DLP и `confidentialPaths` | Среда исполнения (Sandbox) |
|---|---|---|---|
| `trusted-local` | Локальные vLLM, Ollama, внутренний закрытый контур | Без цензуры кода; маскируются только мастер-ключи `~/.bb` | Полный доступ к worktree и локальной сети сборки |
| `trusted-cloud` | Anthropic API (Zero Data Retention), OpenAI Enterprise, Vertex AI | Разрешён `confidentialPaths`; скраббинг production-ключей (§22.1) | Worktree Jail + корпоративный прокси пакетов |
| `public` | OpenCode free, веб-Gemini (Argon/Carbon), публичные пулы | Строгий DLP, RFC ASCII-маскирование, физическое исключение `confidentialPaths` | Строгий bwrap, `--unshare-net`, Snapshot Sandbox без `.git` |

**Разделение ролей на публичных маршрутах:**
- `public` + `text-only` (роли `spec`, `architect`, `auditor`, `researcher`): модель получает только предварительно профильтрованный текстовый пакет через Prompt Redaction Engine; доступ к файловой системе и командной оболочке хоста полностью закрыт (`tools: []`).
- `public` + `tool-enabled` (роль `executor` / `code`): агент запускается исключительно внутри стерильного Snapshot Sandbox на базе bubblewrap.

**Принцип Fail-Closed:**
Если задача помечена флагом приватности `--privacy strict` либо затрагивает файлы из перечня `confidentialPaths`, а все маршруты уровней `trusted-local` и `trusted-cloud` недоступны (исчерпана квота, rate limit, сбой сети), задача **ОБЯЗАНА** немедленно перейти в статус `blocked` с ошибкой:
`route-unavailable: confidential task requires trusted route, public fallback is prohibited`.
Автоматический даунгрейд на публичные маршруты для конфиденциальных задач **КАТЕГОРИЧЕСКИ ЗАПРЕЩЁН**.

## Последствия

- **Безопасность:** полностью исключены утечки истории Git, токенов из `.git/config` и конфиденциальных исходных кодов при использовании бесплатных и веб-моделей.
- **Надёжность слияния:** RFC-совместимые ASCII-маски устраняют сбои синтаксических анализаторов, AST-парсеров и поломки `git apply`.
- **Защита от эксфильтрации:** односторонняя природа подстановки секретов и запрет их появления в добавленных строках гарантируют защиту от атак через Prompt Injection.
- **Производительность:** накладные расходы на создание слепка через `git archive` и запуск через `bubblewrap` составляют менее 10–20 мс на задачу, что не оказывает заметного влияния на длительность итераций.
- **Ограничения:** для запуска тестов внутри песочницы на публичном маршруте все зависимости должны быть предварительно установлены или закешированы, так как внешняя сеть отключена (`--unshare-net`).
