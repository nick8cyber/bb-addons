# Privacy Blur — маска через CSS Custom Highlight API

## Контекст

Плагин должен скрывать фрагменты текста в DOM, которым владеет React bb. Обёртка совпадений в `<span>` ломает сверку React: при обновлении узлов возможны `removeChild`-ошибки и пропажа текста. Наложение абсолютных блоков поверх `getClientRects()` требует пересчёта на каждый скролл и ресайз, не учитывает обрезку прокручиваемых контейнеров и рисуется поверх модальных окон.

## Решение

Совпадения отмечаются диапазонами (`Range`) в `CSS.highlights` под именем `bb-privacy-blur` и красятся через `::highlight()`. DOM bb не меняется. В браузерах без Highlight API ставится атрибут `data-privacy-blur-hit` на родителя совпадения, и он размывается целиком.

Маска непрозрачная: прозрачный текст, сплошной фон и `text-shadow` того же цвета. `::highlight()` не поддерживает `filter`, а полупрозрачный фон с тенью оставлял читаемую форму букв (замечание владельца 05.11).

Сканирование идёт синхронно в колбэке `MutationObserver`. Колбэк — микрозадача до отрисовки, поэтому новый текст не попадает в кадр открытым. Пересканируются только изменённые текстовые узлы и добавленные поддеревья; диапазоны отсоединённых узлов чистятся после удалений.

Слова, которые не ловятся регуляркой, собираются из двух источников: сервер (проекты, хосты, ОС, git, настройки) и фронтенд (хост страницы, серверы, сайдбар). Серверные кэшируются в `localStorage`, чтобы при включении режима они действовали до ответа RPC.

## Последствия

- Охват по умолчанию узкий: шаблоны и известные слова. Заголовки тредов и имена людей — опции, потому что широкое скрытие делает интерфейс бесполезным для показа.
- Текст, разбитый подсветкой синтаксиса на несколько узлов, ловится по частям.
- Адресная строка, тултипы и canvas вне досягаемости плагина.
