# provider-agy — выбор аккаунта пула с учётом модели

## Контекст

1. В пуле появляются аккаунты разных тарифов. Часть моделей есть только на старшем тарифе, часть — на всех.
2. Аккаунт закреплялся за тредом до разбора модели, ротация по квоте модель не учитывала, каталог моделей снимался с одного аккаунта. Модель, которой у закреплённого аккаунта нет, заканчивалась отказом `Unknown model ID`.
3. Запрос владельца: дешёвую модель обслуживать обычными аккаунтами, а старший тариф подключать к ней только когда все обычные стоят из-за лимитов; модели старшего тарифа — только на аккаунтах, где они есть.
4. Отказ Google «service disabled … Terms of Service» не распознавался: такой аккаунт оставался в ротации.

## Решение

1. Возможности аккаунта определяются его собственным ответом `agy models`, а не тарифом и не списком имён в коде. Каталог хранится по аккаунтам в локальном файле инстанса.
2. Каталог моделей провайдера — объединение каталогов аккаунтов в ротации.
3. Выбор аккаунта учитывает модель в четырёх точках: старт треда, ротация, смена модели посреди треда и возобновление, отказ по модели в полёте.
4. Отдельного понятия «тариф» или «дорогой аккаунт» в коде нет: порядок задаёт существующий числовой `priority`. Аккаунт старшего тарифа получает `priority` ниже и для общей модели вступает последним; для своей модели он единственный кандидат.
5. Отказ по Terms of Service — отдельная причина `tos-disabled`: бессрочная парковка без автоповторов, снятие только вручную.

Контракт — `docs/specs/provider-agy-acp.md` §2.3 (ревизия 13.2).

## Последствия

- Имена и состав моделей старшего тарифа знать заранее не нужно: они появятся в каталоге после первого опроса такого аккаунта.
- Тред, начатый на аккаунте старшего тарифа, пока обычные стояли, остаётся на нём до конца (sticky).
- Кулдаун по-прежнему один на аккаунт: исчерпанная квота одной группы моделей выводит аккаунт из выбора и для остальных.
- Раз в 6 часов родной `agy models` запускается по каждому аккаунту в ротации, не больше двух одновременно.

## Отклонённые варианты

- Зашить соответствие «тариф → модели»: устаревает при каждой смене линейки и требует знать тариф аккаунта.
- Жёсткий запрет старшему тарифу обслуживать общую модель: владелец выбрал «в последнюю очередь», и это уже даёт `priority`.
- Кулдаун по группе моделей: отдельная задача, меняет формат общего файла состояния.

## Дополнение 18.11 — по живому тесту

Первый живой запрос модели старшего тарифа на пустом каталоге открыл сессии на всех обычных аккаунтах подряд, а ответ Google о проверке аккаунта ушёл пользователю текстом. Решения (спека §2.3 пп. 9–12, ревизии 13–13.2):

1. **Сначала каталоги, потом выбор.** На холодном старте выбор аккаунта ждёт опроса `agy models` у аккаунтов без каталога (не дольше 30 с); перебор «наугад» запрещён. Отказ по модели — не больше одного переезда и только на аккаунт, где модель точно есть.
2. **Проба каталога — через `HOME` аккаунта.** `--gemini-dir` есть только у `agy acp`; с `agy models` он давал справку и код 2, поэтому каталоги до ревизии 13.2 не заполнялись. Неуспех пробы пишется в лог.
3. **`validation-required` — отдельная бессрочная парковка.** Google просит владельца подтвердить аккаунт: автоповторов нет, снятие вручную. В тексте ответа модели распознаётся только точная форма `agy`, чтобы обычный ответ со словами «verification required» не останавливал аккаунт.
4. **Припаркованный аккаунт не трогает никто**, включая usage-pro (спека usage-account-display §6 п. 4а): ни фоном, ни кнопкой обновления.
5. **Журнал переездов** в локальном логе обёртки — каждое решение пула видно постфактум.

## Дополнение 19.11 — eligibility-отказ со ссылкой проверки = validation-required (PLUG-332)

Решение владельца 19.11: отказ Google по допуску, в тексте которого есть просьба или ссылка проверки аккаунта (`verify your account` — в том числе без «to continue» — или URL `accounts.google.com`), приравнивается к `validation-required`. Такой отказ требует авторизации владельца в браузере, поэтому суточный кулдаун для него убран: парковка бессрочная (`parkedReason: "validation-required"` + `ineligibleAtMs` + `lastError`, без `cooldownUntilMs`), автоповторов нет, снятие только вручную после проверки. Предохранитель массовой парковки проверяется до постановки метки. Отказ без просьбы/ссылки проверки (регион, общий eligibility-отказ) — прежний кулдаун 2 ч; 24 ч `AGY_INELIGIBLE_COOLDOWN_MS` остаётся только у `auth-dead`. Контракт — `docs/specs/provider-agy-acp.md` §2.3 п. 11 (ревизия 15).
