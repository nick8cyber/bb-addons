# Live Call — звонок как тред BB на своём провайдере

## Решение

Каждый звонок — тред BB в отдельном проекте «Звонки» (решение владельца 02.11). Плагин регистрирует скрытый провайдер «Live Call». Его мост не вызывает модель, а только отображает звонок. Фразы владельца становятся сообщениями пользователя: первая — через `threads.spawn`, следующие — через `threads.send`. Реплики агента — `agentMessage`. Проактивные доклады — дополнительные сообщения в открытом ходе. Итог — последнее сообщение.

## Почему

Транскрипт виден как обычная переписка. Звонок находится поиском, на него можно сослаться `@thread`, его читают другие агенты. Спайк ([research/spike-provider](../../plugins/bb-plugin-live-call/research/spike-provider/)) подтвердил: транскрипт нативный, канал сервер → мост работает, ход открыт 121 с без сбоев, провайдер скрывается из выбора агентов.

## Открыто

- Скрытие сделано через `provider/health → not_installed` — статус используется не по назначению. Нужно проверить, как открытый тред звонка выглядит в интерфейсе.
- Ход на 60 минут не проверен.

## Следствие (11.11): иконка провайдера вместо эмодзи в заголовке

Тред звонка получил иконку провайдера «live-call»: плагин регистрирует `slots.experimental_providerIcon` (`providerKind: "agent"`, иконка — та же lucide-трубка `live-call/phone`). Нативный список тредов и плагины списков (compact-ui) рисуют её на месте типа провайдера. Эмодзи 📞 из заголовка «📞 Звонок …» убран: новые треды — «Звонок ДД.ММ ЧЧ:ММ», существующие переименованы разово через `bb thread update --title` (311 шт.). Без регистрации `ProviderIcon` рисовал фолбэк-глиф.

## Запасной вариант

Своя страница «📞 Звонки» со списком и транскриптом из хранилища плагина. Работает точно, но звонки не будут тредами BB.
