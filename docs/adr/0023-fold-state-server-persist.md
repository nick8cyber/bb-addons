# Compact UI — серверная персистентность свёрнутости проектов

## Решение

Состояние свёрнутости проектов в свёрнутом списке сайдбара хранится на сервере: `bb.storage.kv`, ключ `collapsedProjects` (массив id, ≤500). Апп читает его при загрузке через RPC `collapsed_projects_get` и пишет через `collapsed_projects_set` с `origin` окна; сервер публикует `collapsed-projects` в realtime-канал, открытые окна применяют чужие изменения и пропускают своё эхо. Локальный toggle до завершения гидратации защищён `foldDirty`.

## Почему так, а не иначе

- **`uiPreferences` не подходит**: `UiPreferenceKey` — закрытый enum, куда `sidebar.collapsedProjects` не входит. Одноимённый преференс нативного списка живёт в плагин-хранилище thread-list и недоступен посторонним.
- **Настройки плагина** на аппе — только чтение (`useSettings().values`), запись возможна лишь с сервера и светилась бы в UI настроек, чего состояние свёрнутости не должно.
- **Локальное хранилище окна** не решало бы синхронизацию между устройствами — требование владельца.
- `kv` + realtime-канал дают персист и конвергенцию открытых окон без миграций и без влияния на нативный список.

## Следствия

Плагин не читает и не пишет преференсы нативного списка — списки независимы. `origin` клиента — случайный id на маунт, поэтому эхо своих записей отсекается, а чужие применяются всегда.
