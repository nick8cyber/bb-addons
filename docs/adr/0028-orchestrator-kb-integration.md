# orchestrator — встроенная база знаний (KB), команды CLI, MCP-инструменты и интеграция с release

## Контекст

1. **Разрозненность и забывчивость (инцидент 16.11):** База знаний стенда жила в отдельном bash-скрипте `~/.local/bin/kb`, управляющем git-репозиторием KB (`~/.bb/kb` / `~/kb`). Агенты в инциденте 16.11 правили файлы в KB обычными файловыми инструментами (`edit_file`, `write_file`) в обход утилиты `kb`. В результате правки оставались незакоммиченными в локальном дереве, а `kb sync` не отправлял их в GitHub-зеркало (второй хост в Стокгольме не видел обновлений).
2. **Флаг `--kb` в `orchestrator release` не писал в KB:** В конвейере выкладки параметр `--kb <note>` сохранял строку только в локальную SQLite-таблицу `releases` и передавал в чат, но физически в репозиторий KB ничего не записывал и не вызывал синхронизацию.
3. **Отсутствие на других установках:** При развёртывании плагина `orchestrator` на новых машинах (у других пользователей, в контейнерах) утилиты `kb` нет — её требовалось настраивать вручную в `~/.local/bin/kb`.

## Решение

Встроить управление базой знаний (KB) непосредственно в плагин `bb-plugin-orchestrator` как универсальную подсистему (`src/kb.ts`):

1. **Настройка `kb` в плагине оркестратора:**
   ```json
   {
     "kb": {
       "enabled": true,
       "path": "~/.bb/kb",
       "autoSync": true,
       "requireCleanOnRelease": true
     }
   }
   ```
   По умолчанию `path`: `~/kb` (если каталог существует на диске) либо `~/.bb/kb`.

2. **Единое сервисное ядро (`src/kb.ts`):**
   Все операции CLI и MCP выполняются через единый сервис с обязательными инвариантами безопасности:
   - **Изоляция путей (Path Traversal):** канонический путь вычисляется внутри `<kb.path>`, запрещены `..`, внешние симлинки и любые обращения к каталогу `.git/` (отказ `kb-refused: forbidden-path`).
   - **Скан секретов:** записываемый контент проверяется шаблонами утечек оркестратора (§22) до записи на диск и коммита (отказ `kb-refused: secret-leak`).
   - **Точечный git add:** строго `git add -- <относительный_путь>`, исключающий случайный захват чужих файлов.
   - **Блокировка (File Lock):** эксклюзивный замок `<kb.path>/.git/orchestrator-kb.lock` на время мутаций (`write`, `append`, `sync`) предотвращает гонки между параллельными тредами.
   - **Чистота коммитов:** авторство из `commitIdentity` репозитория, без `--no-verify` и без трейлеров `Co-Authored-By`.

3. **Команды CLI (`bb orchestrator kb`):**
   - `bb orchestrator kb list [--json]` — список документов базы знаний (исключая `.git/`).
   - `bb orchestrator kb search <текст> [--limit N] [--json]` — полнотекстовый поиск по `.md` файлам.
   - `bb orchestrator kb read <путь>` — вывод содержимого документа.
   - `bb orchestrator kb write <путь> [--message <msg>] [--file <input>]` — атомарная запись файла из stdin или пути с созданием каталогов, точечным `git add -- <путь>`, коммитом `kb(<task|thread>): <путь>` и вызовом `sync` при `autoSync: true`.
   - `bb orchestrator kb append <путь> [--message <msg>] [--file <input>]` — добавление в конец документа с коммитом.
   - `bb orchestrator kb sync` — `git pull --rebase` + `git push` в upstream с блокировкой и разбором ошибок.
   - `bb orchestrator kb status [--json]` — статус репозитория KB (`git status --porcelain` и сверка с upstream).

4. **Инструмент MCP (`orchestrator_kb`):**
   - Единый инструмент MCP с параметрами: `action` (`list` | `search` | `read` | `write` | `append` | `sync` | `status`), `path`, `content`, `query`, `message`, `limit`.
   - **Матрица ролей (RBAC):** роль `auditor` ограничена операциями чтения (`list`, `search`, `read`, `status`); вызовы `write`, `append`, `sync` отклоняются с ошибкой `permission-denied`. Роли `executor` и `orchestrator` имеют полный доступ.

5. **Интеграция с конвейером `release`:**
   - **Шаг 1 (Приёмка):** при `kb.enabled: true` и `requireCleanOnRelease: true` (по умолчанию) проверяется `git -C <kb.path> status --porcelain`. При наличии незакоммиченных изменений — отказ `release-refused: uncommitted-kb: в базе знаний незакоммиченные файлы (<файлы>)`.
   - **Шаг 7 (`postPublish`):** при наличии параметра `--kb "<заметка>"` оркестратор автоматически:
     - формирует детерминированный файл `<kb.path>/releases/<YYYY-MM-DD>-<KEY>.md` (дата UTC, шаблон с метаданными задачи, коммита и заметкой);
     - соблюдает идемпотентность: при повторном вызове с тем же содержимым или при наличии коммита `rel(<KEY>): ...` повторный коммит пропускается;
     - коммитит: `git commit -m "rel(<KEY>): <заметка>"`;
     - выполняет `kb sync` в upstream KB; при сетевой ошибке синхронизации релиз кода не откатывается, а строка координатору рапортует `KB: записан локально, ошибка синхронизации: <ошибка>` (`pp.kbSyncFailed`); при успехе — `KB: записан релиз releases/<YYYY-MM-DD>-<KEY>.md (синхронизировано)` (`pp.kbSuccess`).

6. **Обратная совместимость хоста:**
   - Скрипт `~/.local/bin/kb` заменяется на враппер `exec bb orchestrator kb "$@"`.

## Следствия

- Агенты не могут обойти коммит и синхронизацию базы знаний.
- Заметки выкладки фиксируются детерминированно в UTC-файлы `releases/<YYYY-MM-DD>-<KEY>.md` без риска потери кода при сетевых сбоях пуша KB.
- Полная изоляция от path traversal, утечек секретов и гонок параллельных тредов.
- Контракт: [спека orchestrator](../specs/orchestrator.md) §26 (r33.8), [спека release](../specs/orchestrator-release.md) §2 (r11.7).
