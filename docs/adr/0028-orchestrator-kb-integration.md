# orchestrator — встроенная база знаний (KB), команды CLI, MCP-инструменты и интеграция с release

## Контекст

1. **Разрозненность и забывчивость (инцидент 16.11):** База знаний стенда жила в отдельном bash-скрипте `~/.local/bin/kb`, управляющем git-репозиторием KB (`~/.bb/kb` / `~/kb`). Агенты в инциденте 16.11 правили файлы в KB обычными файловыми инструментами (`edit_file`, `write_file`) в обход утилиты `kb`. В результате правки оставались незакоммиченными в локальном дереве, а `kb sync` не отправлял их в GitHub-зеркало (второй хост в Стокгольме не видел обновлений).
2. **Флаг `--kb` в `orchestrator release` не писал в KB:** В конвейере выкладки параметр `--kb <note>` сохранял строку только в локальную SQLite-таблицу `releases` и передавал в чат, но физически в репозиторий KB ничего не записывал и не вызывал синхронизацию.
3. **Отсутствие на других установках:** При развёртывании плагина `orchestrator` на новых машинах (у других пользователей, в контейнерах) утилиты `kb` нет — её требовалось настраивать вручную в `~/.local/bin/kb`.

## Решение

Встроить управление базой знаний (KB) непосредственно в плагин `bb-plugin-orchestrator` как универсальную подсистему:

1. **Настройка `kb` в плагине оркестратора:**
   ```json
   {
     "kb": {
       "enabled": true,
       "path": "~/.bb/kb",
       "autoSync": true,
       "requireCleanOnRelease": true
     }
   }
   ```
   По умолчанию `path`: `~/.bb/kb` (или `~/kb`, если каталог существует).

2. **Команды CLI (`bb orchestrator kb`):**
   - `bb orchestrator kb list [--json]` — список документов базы знаний.
   - `bb orchestrator kb search <текст> [--limit N] [--json]` — полнотекстовый поиск по `.md` файлам.
   - `bb orchestrator kb read <путь>` — вывод содержимого документа.
   - `bb orchestrator kb write <путь> [--message <msg>] [--file <input>]` — атомарная запись файла из stdin или файла, с автоматическим `git add` и коммитом `kb(<task|thread>): <путь>`, и автосинком при `autoSync: true`.
   - `bb orchestrator kb append <путь> [--message <msg>] [--file <input>]` — добавление в конец документа с коммитом.
   - `bb orchestrator kb sync` — надёжный `git pull --rebase` + `git push` с обработкой ошибок.
   - `bb orchestrator kb status [--json]` — статус репозитория KB (наличие незакоммиченных файлов, ветка, синхронизация с upstream).

3. **Интеграция с конвейером `release`:**
   - **Шаг 1 (Приёмка):** если задача затрагивала файлы KB или включён `requireCleanOnRelease`, конвейер проверяет статус репозитория KB. При наличии незакоммиченных правок — отказ `release-refused: uncommitted-kb` («в базе знаний незакоммиченные файлы: <список>»).
   - **Шаг 7 (`postPublish`):** при наличии параметра `--kb "<заметка>"` оркестратор автоматически формирует запись релиза в `<kb.path>/releases/<YYYY-MM-DD>-<KEY>.md` (или аппендит в сводку проекта), коммитит с сообщением `rel(<KEY>): <заметка>` и выполняет `kb sync`.

4. **Обратная совместимость хоста:**
   - Скрипт `~/.local/bin/kb` заменяется на лёгкий враппер `exec bb orchestrator kb "$@"`.

## Следствия

- Агенты больше не забывают коммитить и пушить факты в базу знаний.
- Выкладка релиза гарантированно оставляет след в KB на обоих хостах.
- База знаний становится портабельной частью экосистемы orchestrator.
- Контракт: [спека orchestrator](../specs/orchestrator.md) §26 (r33.8), [спека release](../specs/orchestrator-release.md) §2 (r11.7).
