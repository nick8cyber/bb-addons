# ADR-0040: favorite-models — единый версионный KV `favorites:store` и канонический providerId

Статус: принято (PLUG-385, аудит PLUG-382).

## Контекст

Плагин избранных моделей изначально хранил данные в раздельных KV-ключах (`favorites:map`, `favorites:labels`, `favorites:config`), а провайдера идентифицировал подписью таба в DOM. Аудит живого поведения показал системные рассинхроны: SDK отдаёт `acp-devin`/`acp-opencode`, а звёзды писались под `devin`/`opencode` → меню в открытом треде показывало «нет избранного» при полном сервере; три разных провайдера схлопывались в `agy`; отсутствие версионности позволяло старым снимкам откатывать чужие правки.

## Решение

1. **Один версионированный ключ `favorites:store`** — атомарное read-modify-write под `withStoreLock`; миграция legacy-ключей внутри того же лока; `version` инкрементится каждой успешной записью.
2. **Канонический providerId** — избранное хранится под реальным id провайдера из каталога; подписи табов сопоставляются через `normalizeProviderId` (общая для клиента/сервера/CLI); существующие ключи переносятся в loadOrMigrate. Провайдеры с похожими именами (`Google Antigravity`, `ACP Web Gemini`, `Antigravity (agy)`) остаются различными.
3. **Ключ модели = `label · route`** — полная подпись пикера; записи без маршрута сохраняют совместимость (применяются ко всем маршрутам) и по возможности восстанавливаются по меткам.
4. **`baseVersion` в `setFavorites`** — полная перезапись только от известной базы, иначе 409.
5. **Живой синк вместо boot-снимка** — refetch по focus/visibility + интервал; очередь мутаций с повтором или честный откат.

## Последствия

- Кросс-девайс и кросс-контекст консистентность: одни и те же ключи независимо от пути записи.
- Потеря оффлайн-записей исключена (очередь) либо явно показана (откат).
- Оставшийся долг: fallback-таблица имён провайдеров может временно откатывать канон к `provider-*` при пустом каталоге (неблокер, ремарка ревью PLUG-385); `doctor` не видит чужие модели внутри валидных групп.
