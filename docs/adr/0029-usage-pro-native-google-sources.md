# usage-pro — квоты Google только через родной клиент

## Контекст

1. С 15.11 usage-pro показывал выделенный аккаунт провайдера `acp-antigravity` отдельной карточкой и собирал её сам: читал `~/.gemini/antigravity-acp/acp_token.json`, выпускал access-токен по refresh grant и вызывал `loadCodeAssist`, `retrieveUserQuotaSummary`, `fetchAvailableModels` на `cloudcode-pa` / `daily-cloudcode-pa` с собственным заголовком `User-Agent` вида `antigravity/usage-pro/…`.
2. Условия Antigravity (п. 6) называют нарушением доступ к сервису через сторонний софт и допускают за это приостановку аккаунта. Прямой сборщик — сторонний клиент на продуктовом логине, какой бы заголовок он ни слал.
3. Карточка пула agy в том же плагине квоты получает иначе: запускает родной `agy --output-format json -p /usage` с `HOME` аккаунта. В Google ходит сам бинарь Google, своими кредами и своими заголовками.

## Решение

1. usage-pro не обращается к Google напрямую и не читает OAuth-креды Antigravity. Квоты Antigravity — только через родной `agy … -p /usage`.
2. Прямой сборщик и синтезируемая карточка `acp-antigravity` удаляются. Выделенный аккаунт виден на табе agy как аккаунт пула вне ротации (`priority = 0`).
3. Аккаунты вне ротации опрашиваются только по явному запросу пользователя (`force`), без фонового опроса.
4. Правило общее для плагина: новый источник квот Google допускается, только если данные отдаёт родной клиент Google. Usage-ресурсы `acp-*` от плагинов-источников usage-pro не запрашивает.

Контракт поведения — `docs/specs/usage-account-display.md` §6 (ревизия 3).

## Последствия

- Отдельного таба `acp-antigravity` нет.
- Окна выделенного аккаунта берутся из `/usage` родного CLI: производных модельных окон и суточного окна из `fetchAvailableModels` больше нет.
- Лимиты выделенного аккаунта обновляются кнопкой, не сами.

## Отклонённые варианты

- Оставить прямой сборщик с «честным» `User-Agent`: сторонний клиент на продуктовом логине остаётся сторонним при любом заголовке.
- Запрашивать квоты через ACP-сессию `agy_acp_server`: каждая проверка создаёт сессию агента; отдаёт ли сервер квоты по ACP, не проверялось.
