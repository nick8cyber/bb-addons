# ADR-0043: Чистый research-пакет web-Gemini (PLUG-404)

## Контекст

Встроенный поиск Google в веб-Gemini работает: 24.11 Neon (#1982) и Hydrogen (#1994) нашли свежий факт (npm `opencode-ai` 1.19.6 от 17.11) со ссылками и карточками источников. Но в двух ходах модель не искала:

- **#1938, Neon, исследование PLUG-399.** Ответ «отключён вызов инструментов и веб-поиска (0 доступных вызовов)». Первая строка шапки про встроенный поиск (PLUG-370, PLUG-384) в пакете была. Остальной пакет ей противоречил: протокол `<tool …/>` со строгим «только XML», три команды `bb_*`, «ответ без тегов считается финальным», «лимит раундов инструментов: 8», служебные разделы BB (Report-back contract с `bb tasks` CLI, Project context, Sub-tasks, Attachments, Recent comments).
- **#1986, Hydrogen.** Шаблонный защитный отказ «Я всего лишь ИИ, работающий с текстом». В один пакет попали две несовместимые задачи: рейтинг 40 моделей целиком и тест поиска в «Additional instructions». Рядом в пресетах лежали мета-формулировки вида «поиск у тебя есть и разрешён… не отвечай, что доступа нет».

## Решение

1. В лёгком research-режиме (`research && !write`) пакет веб-модели состоит только из короткой утвердительной строки поиска («Найди ответ в интернете через поиск Google. Для каждого факта укажи ссылку на источник и дату.») и текста задачи. Протокол инструментов, лимит раундов, `bb_*` и служебные разделы BB по закрытому списку не передаются. Цикл дозапроса не запускается (inner-agent §4.6).
2. Формулировки для веб-моделей — короткие и утвердительные. Без отрицаний, утверждений о правах и возможностях модели и мета-указаний «не отвечай, что…»: они включают защитные отказы.
3. Одна задача на ход. Тесты и уточнения — отдельной маленькой задачей, а не дописыванием к чужой большой.
4. Маскировка в research-пакете точечная: свой ключ и id BB. Общий шаблон `ABC-123` портит имена моделей (`GLM-5.3-Flash`).
5. Вывод «поиск не работает» делается только по живому тесту с проверяемым фактом, а не по словам модели о себе.

## Последствия

- Исследования на Neon/Hydrogen можно раздавать одним этапом. Двухэтапная схема (agy собирает, Neon ранжирует) остаётся запасной.
- Пресеты `neon-research`, `hydrogen-research`, `web-gemini-research` переписаны в утвердительном стиле (24.11).
- Приёмка PLUG-404 — живая, на исходном seed-тексте #1938: 3× Neon, 2× Hydrogen, не меньше 5 URL первичных источников в каждом ответе.
