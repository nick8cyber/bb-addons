# Voice STT — живой ввод через перетаскиваемую плавающую кнопку

## Контекст

Живой режим `voice-stt` стримит речь в Gemini Live во время записи, поэтому текст готов через 1–2 с после конца. Нужен вход в этот режим, который удобен и на десктопе, и в мобильном клиенте bb. Ограничения SDK и клиента:

- плагинные `composer.actions` рисуются только в развёрнутом композере; на мобильном композер свёрнут, пока по нему не тапнешь, — кнопки не видно;
- официального способа заменить нативный микрофон нет;
- на iOS запуск `getUserMedia` и аудиоконтекста подвешивает отрисовку на время запуска;
- при открытой клавиатуре высота окна падает, и элементы с `position: fixed` наезжают друг на друга.

## Решение

1. **Вход — плавающая кнопка** в `experimental_appOverlay`. Видна всегда, пока включён `liveInput`. В строке ввода остаётся только нативный микрофон bb: плагин не добавляет свою кнопку и не скрывает нативную.
2. **Кнопка перетаскивается.** Позиция хранится в `localStorage` долями свободного поля окна, поэтому переживает поворот экрана и смену размера. Своя на каждом устройстве.
3. **Касание не запускает запись.** На касании кнопка сразу краснеет и будит только AudioContext (требование iOS к жесту). Режим решается по жесту: тап — запись до следующего тапа, удержание 300 мс — запись, пока держишь, сдвиг больше 10 px — перенос. Во время переноса кнопка двигается прямой записью `style.left/top`, без перерисовок React.
4. **Плашка записи — сама кнопка.** Тап по ней завершает запись и вставляет текст. Отдельных кнопок «Вставить», «Отмена», «Копировать» и крестика нет. Плавающая кнопка всегда выше плашки, без `transform` в позиционировании: пульс не сдвигает её.
5. Текст только вставляется в черновик, сообщение не отправляется.

## Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Кнопка в `composer.actions` | Мелкая и не видна в свёрнутом композере на мобильном. |
| Кнопка в правом нижнем углу | Перекрывала отправку на мобильной раскладке. |
| Одна своя кнопка вместо нативной (CSS по `data-icon="Mic"`) | Работала, но владелец выбрал нативный микрофон в строке ввода плюс отдельную плавающую кнопку. Скрытие чужого элемента CSS-ом хрупко при обновлениях bb. |
| Старт записи на касании | Подвисала отрисовка на iOS: кнопка не ехала за пальцем и прыгала только на отпускании. |
| Кнопки «Вставить»/«Отмена» в плашке | Лишние элементы; тап по плашке проще. |

## Последствия

- Первый промежуточный текст появляется примерно на 0,3 с позже: сокет открывается после распознавания жеста, а не на касании.
- Отмены на мобильном нет (Esc есть только на десктопе). Лишний текст удаляется из черновика вручную.
- Перезагрузка плагина обрывает идущую диктовку. Плагин перезагружают только когда нет активной сессии (`live-session: connecting` без `finished` в логе сервера).
- Кнопка может закрывать элементы у края окна. Это решается переносом, а не фиксированной позицией.
