# provider-agy — токен аккаунта пула хранится в файле аккаунта, а не в системном хранилище ключей

## Контекст

1. Пул `provider-agy` изолирует аккаунты домашними каталогами: у каждого свой `<дом аккаунта>/.gemini/antigravity-cli/antigravity-oauth-token`.
2. agy читает токен из системного хранилища ключей раньше файла. Хранилище (macOS Keychain, Secret Service, Windows Credential Manager) — одна ячейка на пользователя машины.
3. Отзыв с macOS 19.11: после ротации agy продолжал работать под прежним аккаунтом из Keychain и падал по лимитам. Стенд на Linux без Secret Service этого не видел: там agy сам уходит в файл.
4. В бинарнике agy есть встроенный выбор файлового хранения по окружению: при признаке SSH-сессии он пишет в лог «Using file-based token storage because SSH session detected» и к хранилищу ключей не обращается. Проверено 20.11 на настоящем agy (Linux), в том числе `agy models` на аккаунте пула.

## Решение

Каждый запуск agy на аккаунте пула получает в окружении `SSH_CONNECTION` (настоящее значение хоста или заглушка `127.0.0.1 0 127.0.0.1 0`). Контракт — [provider-agy-acp.md](../specs/provider-agy-acp.md) §2.3 п. 14. Прямой режим (без пула) и relay-дом не затрагиваются. Отключение — `AGY_KEYRING=1`.

## Отклонённые варианты

- **Синхронизировать токен выбранного аккаунта в Keychain перед запуском** (`security add-generic-password -U`, предложено в отзыве). Отклонено: общая ячейка даёт гонку между параллельными тредами на разных аккаунтах, обновлённый agy токен остаётся в ячейке, а не в файле аккаунта, личный вход владельца машины затирается, токен виден в аргументах команды.
- **Подменять `HOME` на дом аккаунта для всех запусков.** Не подтверждено, что это отключает хранилище ключей на macOS; для `agy acp` изоляция идёт через `--gemini-dir`.

## Последствия

- Команды, которые agy запускает в треде, тоже видят `SSH_CONNECTION`.
- Аккаунты, добавленные на macOS до этой правки, могут иметь токен только в Keychain — их добавляют заново через `scripts/add-account.mjs`.
- На macOS решение не проверено (Mac на стенде нет); поведение выведено из общего кода agy и проверки на Linux.
- Замечания ревью (PLUG-357): маркер имеет абсолютный приоритет и последнее слово над `options.envVars` сессии (ключ `SSH_CONNECTION` отбрасывается из `envVars` при запуске пул-аккаунта) и над `install.env` реестра установок на всех путях запуска аккаунтов пула (`session/new`, `session/load`, опрос `agy models`, включая пробники каталога, stream-json, `add-account`). В прямом режиме, в relay и при `AGY_KEYRING=1` ключ `SSH_CONNECTION` из `envVars` не фильтруется.
