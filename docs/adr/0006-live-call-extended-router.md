# Live Call — режимы Extended (по умолчанию) и Быстрый

## Решение

Два режима, переключаются в один тап, голосом или клавишей, в том числе посреди звонка:

- **🧠 Extended (по умолчанию)** — голос на `gemini-3.8-live-extended-thinking` **без инструментов**. Инструмент выбирает вторая сессия `gemini-3.8-live` (ROUTER) по словам владельца. Сервер исполняет инструмент и вставляет результат в голосовую сессию как `[СИСТЕМА] …`. Сам Extended инструмент не запускает, он только предлагает.
- **⚡ Быстрый** — одна сессия `gemini-3.8-live`, нативные инструменты `NON_BLOCKING`.

Переключение посреди звонка — это новая сессия с пересказом разговора (тот же механизм, что при смене ключа). Пока ждёт подтверждение, переключение заблокировано. Если Extended перестал отвечать, плагин предлагает «Перейти на Быстрый» и модель без слова владельца не меняет.

## Пересмотр 03.11

Владелец: Extended — по умолчанию, второй режим называется «Быстрый» (было 02.11: «Обычный» по умолчанию). В коде `defaultMode` = `extended`, значение `normal` в интерфейсе — «Быстрый». При переключении слышен один голос: старая сессия глушится, новая не здоровается заново.

## Почему

Нативные вызовы инструментов у Extended Thinking на стороне Google не работают: 0 из 21 сессии. Проверено своим клиентом и официальным SDK, текстом и живым голосом, на LOW, MEDIUM и HIGH, v1alpha и v1beta. Модель говорит «сейчас проверю», через несколько секунд — «system error». Базовая модель с тем же кодом вызывает инструмент за ~1 с. О том же сообщают другие разработчики (форум Google AI, python-genai #3015). Связка VOICE + ROUTER прошла 7 из 7 сценариев.

## Условия режима Extended

- Пока ждёт подтверждение, реплики владельца в ROUTER не идут. Без этого «запускай» приводит к повторному вызову и второму агенту — воспроизведено.
- Повторы вызовов отбрасываются, не больше 3 вызовов на реплику. ROUTER получает реальный результат вызова, а не «done» — иначе зацикливается (воспроизведено).
- Результаты одной реплики уходят в голосовую сессию одним пакетом.
- Когда Google починит нативные вызовы, `bb call probe` это покажет. Упрощение Extended до одной сессии — со слова владельца.

[Контракт и приёмка](../specs/live-call.md) — §1, §2.1, §7.1.

## Пересмотр 2 (03.11, владелец): Extended отключён

Владелец: «Extended в любом случае придётся отключить, потому что он сломанный на стороне Google. Оставляем просто обычный быстрый режим без всяких двойных костылей».

Почему:
- модель `gemini-3.8-live-extended-thinking` не вызывает инструменты (пробы: 0 из 18);
- в половине звонков она сама добавляет «произошла системная ошибка» (PLUG-102: 5 из 10 звонков, прямые сессии 4 из 6);
- схема из двух моделей (голос и помощник) дала неверные ответы: помощник действует вслепую.

Решение:
- любой звонок — одна сессия `gemini-3.8-live` с инструментами;
- сервер всегда открывает `normal`;
- кадр `switch_mode` игнорируется, инструмент `switch_mode` не объявляется;
- переключателя режима и команды `Mod+Shift+K` в интерфейсе нет;
- код Extended и помощника сохранён только для тестов (`allowExtended`).

Блок правил владельца (контракт §12.12) — и в обычном звонке.
