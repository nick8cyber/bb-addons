# Порции вместо полного раскрытия

## Решение

Заменить бинарный expandedGroupKeys на временный бюджет обычных корней по каждой группе проекта. Первая граница — ближайшая десятка строго выше исходного лимита, последующие шаги ±10 с нижней границей исходного лимита. Показывать две независимые кнопки «Ещё N» / «Меньше» в одной строке и точный счётчик корней.

## Причины и последствия

Полное раскрытие длинного проекта заполняет панель; порции сохраняют управляемый размер. Бюджет, а не фактическое число показанных строк, позволяет корректно вернуться с неполной последней страницы. Защищённые корни и дети сохраняют старые гарантии видимости и не расходуют обычный бюджет. Число рядов может превышать границу.

Состояние остаётся локальным текущему монтированию, без новой настройки, БД или миграции. При смене visibleThreads бюджеты сбрасываются. B=0 остаётся режимом «всё». Скрытие navigation rail — отдельная незавершённая фича и в эту поставку не входит.

При сокращении списка «Меньше» выбирает наибольшую границу ниже min(бюджет, текущие обычные корни), не ниже B, чтобы не давать холостых кликов. Очистка состояния опирается на ready/projects, а не временные groups. Чистые переходы и счётчики тестируются отдельно от статического SDK UI-харнеса; смена входов UI — через immutable snapshots и подмену хуков либо живой браузер.
