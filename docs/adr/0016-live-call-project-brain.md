# ADR-0016. Мозговой центр звонка по проекту

## Контекст

В ADR-0011 проектный звонок получил инструменты коннектора напрямую в Gemini Live, тогда как мозговой центр реализован только для звонка по треду. Голос самостоятельно выбирает данные и строит выводы. Проверка показала подмену новых регистраций стадией воронки и необоснованные выводы о доставке событий из уведомлений приложения. Замена модели без доступа к данным этого не решает.

## Решение

1. В каждом проектном звонке запускается один скрытый мозговой центр на `acp-devin`, модель `swe-2-flash-medium`, reasoning `medium`. Gemini Live остаётся голосовым интерфейсом. Первое приветствие не ждёт запуска мозга.
2. Для чтения данных мозг использует серверный мост к коннекторам текущего звонка. Мост исполняет только объявленные инструменты с итоговым классом R и без двухшаговой записи; команды, адреса и секреты коннекторов мозгу не выдаются. Интерфейс — последовательный обмен структурированными запросами/результатами через тред мозга; отдельный публичный HTTP endpoint не нужен.
3. Расчёты и диагностика направляются через `brain_ask`; простое чтение и записи голосом сохраняются. Мозг не исполняет записи через мост. Существующий ConfirmationGate остаётся единственной точкой подтверждения голосовых изменений, `brain_task` в проектном звонке не объявляется.
4. Мозгу не требуется целевой тред. Для git используется отдельный worktree; для проекта без git — существующий служебный проект звонков и отдельные файлы контекста звонка. Нет изолированного worktree и нет служебного проекта — мозг недоступен, запуска в общей папке целевого проекта нет.
5. Таймаут, завершение звонка, недоступность провайдера и коннектора имеют явные результаты; данные другого запроса и предыдущая сводка не выдаются как новый ответ.

## Границы

Мозг — агент с оболочкой, его инструкции не являются технической песочницей; это существующая граница доверия провайдера, как в ADR-0009. Данный мост технически ограничивает собственный канал коннекторов и не выдаёт мозгу ключи либо команды доступа к рабочему сервису. Права shell провайдера этой задачей не расширяются. Инструкции агента и файлы публичного репозитория не содержат приватных данных стенда.

Новые метрики и диагностика самих сервисов не появляются автоматически: отсутствие нужного инструмента возвращается как ограничение. Изменения MCP-коннектора конкретного проекта требуют отдельной спецификации в его репозитории.

## Последствия

ADR-0011 п. 1 и контракт §15.4.3 читаются как «одна голосовая сессия плюс мозговой центр», а не запрет на второй мозг. Подробный контракт и приёмка: [live-call-project-brain](../specs/live-call-project-brain.md), связка — §15.9 основного контракта. Поведение звонков по треду сохраняется.
