# Usage Pro — лимиты всех машин сразу

## 1. Зачем
У клиента два сервера в одном BB: `main` (сервер) и `worker` (воркер), на каждом свой аккаунт Claude. Сейчас панель лимитов показывает одну машину за раз через меню «Usage source». Нужно видеть лимиты всех машин одновременно, чтобы понимать, куда отправлять тяжёлые треды.

## 2. Главное правило (не обсуждается)
Лимиты машины запрашивает **сама эта машина** — через её демон, как сейчас делает `getUsage` (сервер берёт провайдеров через `sdk.providers.list({ capability: "usage", hostId })`). Сервер не читает чужие файлы с ключами и не ходит в API провайдера за другую машину. IP запросов к Anthropic не смешиваются.

Проверено 25.11 на клиенте: при `getUsage` по `worker` соединения к Anthropic идут только с `worker` (uid 1000), с `main` — ни одного.

## 3. Что видит пользователь

### 3.1. Меню «Usage source»
- Новый первый пункт **«Все машины»**, под ним разделитель и машины, как сейчас.
- Пункт есть, только если подключённых (не ephemeral) машин с провайдерами usage ≥ 2. Одна машина — интерфейс как сейчас, без изменений.
- При ≥ 2 машинах «Все машины» выбрано по умолчанию. Выбор пользователя запоминается так же, как сейчас запоминается машина.

### 3.2. Вид «Все машины» (поповер)
- Табы провайдеров остаются. Внутри таба — список секций, по одной на машину.
- Шапка секции: точка статуса (онлайн/офлайн), имя машины, бейдж «сервер» у машины-сервера, справа — план (`Team`, `Max`…).
- Под шапкой — существующие карточки аккаунтов этой машины без изменений: окна сессии/недели/моделей, «Сброс: …· через …», цвета (< 80% синий, 80–94% жёлтый, ≥ 95% красный), группировка окон по семействам.
- Несколько аккаунтов на одной машине (Codex, Antigravity) — как сейчас, внутри секции своей машины.
- Строка-подсказка над списком: «Свободнее всего: **<машина>** — N% сессии осталось». Считается по выбранному провайдеру среди машин со статусом ok: у каждой машины берётся самое заполненное окно, выигрывает машина с наименьшим значением; N = 100 − процент её окна сессии (`five-hour`), если его нет — худшего окна. Меньше двух машин с данными — строки нет.
- Состояния секции:
  - провайдер не авторизован → «Claude не подключён» (имя провайдера подставляется) и кнопка «Как подключить» (ссылка на настройки провайдера, как в текущем пустом состоянии);
  - машина офлайн → серая точка, «Машина недоступна · данные N мин назад», последние известные полосы приглушены (opacity ~0.55); данных нет — только текст;
  - ошибка сбора → существующее отображение ошибки аккаунта.
- Высота поповера фиксирована как сейчас (20rem), список прокручивается внутри.
- Внизу: «Обновлено N с назад» и «↻ Обновить» — как сейчас.

### 3.3. Футер сайдбара (закрытый вид) — ОПЦИЯ
- Новая настройка плагина `footerMachines` (boolean, **по умолчанию false**), подпись «Лимиты всех машин в футере», описание «Показывать в закрытом футере мини-полосу каждой машины. Включайте, если в футере есть место».
- Выключено → футер как сейчас, без изменений.
- Включено и машин ≥ 2 → в пилюле футера по каждой машине: короткое имя, мини-полоса (26×5 px) и процент худшего окна выбранного провайдера, через разделитель. Имя длиннее 8 символов обрезается с многоточием, полное — в title.
- Ширина не должна ломать футер при ширине сайдбара 260 px и экране 375 px: если не помещается — показывать только проценты без имён.

## 4. Данные
- «Все машины» вызывает существующий RPC `getUsage` с `machineIds` = все подключённые не-ephemeral машины (сервер уже умеет список машин). Один запрос, ответы по машинам изолированы: ошибка одной не ломает другие.
- Кэш и обновление — как сейчас (SWR, `maxAgeMs` 60 с, фоновое обновление раз в 60 с при видимой вкладке).
- Правило двух схем (PLUG-328): если меняется форма ответа `getUsage`, править и серверную схему, и копию схемы внутри `app.bundle.js`. Предпочтительно форму ответа не менять.

## 5. Файлы
- `plugins/bb-plugin-usage-pro/app.bundle.js` — интерфейс (исходника нет, правки прямо в бандле, как в прошлых задачах), `app.css` — стили.
- `plugins/bb-plugin-usage-pro/server.ts` — настройка `footerMachines` (`bb.settings.define`), передача её во фронт тем же способом, что у других настроек плагина.
- Тесты рядом (`*.test.ts`, vitest): расчёт строки «Свободнее всего», видимость пункта «Все машины» (1 и 2 машины), футер при `footerMachines` false/true, изоляция ошибки одной машины.
- Документы: этот файл → `docs/specs/usage-pro-all-machines.md`, раздел в `plugins/bb-plugin-usage-pro/README.md`.

## 6. Не делаем
- Новый плагин — нет, только Usage Pro.
- Суммирование лимитов разных аккаунтов — нет.
- Изменение логики сбора на машинах (Codex, agy, Claude) — нет.
