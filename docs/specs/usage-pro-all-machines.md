# Usage Pro — лимиты всех машин сразу

## 1. Зачем
У клиента два сервера в одном BB: `main` (сервер) и `worker` (воркер), на каждом свой аккаунт Claude. Сейчас панель лимитов показывает одну машину за раз через меню «Usage source». Нужно видеть лимиты всех машин одновременно, чтобы понимать, куда отправлять тяжёлые треды.

## 2. Главное правило (не обсуждается)
Лимиты машины запрашивает **сама эта машина** — через её демон, как сейчас делает `getUsage` (сервер берёт провайдеров через `sdk.providers.list({ capability: "usage", hostId })`). Сервер не читает чужие файлы с ключами и не ходит в API провайдера за другую машину. IP запросов к Anthropic не смешиваются.

Проверено 25.11 на клиенте: при `getUsage` по `worker` соединения к Anthropic идут только с `worker` (uid 1000), с `main` — ни одного.

## 3. Что видит пользователь

### 3.1. Меню «Usage source»
- Новый первый пункт **«Все машины»**, под ним разделитель и машины, как сейчас.
- Пункт есть, только если **настроенных** машин с провайдерами usage ≥ 2. «Настроенные» — не-ephemeral хосты из списка машин BB (виртуальные записи `source:*` не считаются), **независимо от онлайн-статуса**: ушедшая в офлайн машина остаётся в списке и показывает офлайн-состояние (§3.2), а не убирает пункт. Одна машина — интерфейс как сейчас, без изменений.
- При ≥ 2 машинах «Все машины» выбрано по умолчанию. Выбор пользователя запоминается так же, как сейчас запоминается машина — **в памяти сессии, без персистентности** (как сейчас: при перезагрузке сбрасывается на дефолт).
- Меню есть в двух местах — поповер сайдбара и раздел настроек плагина; пункт «Все машины» и поведение одинаковые в обоих.
- Если ранее выбранный провайдер-таб недоступен (нет такого провайдера ни на одной машине, напр. дефолтный `codex` при установке только с Claude) — выбирается первый доступный провайдер.

### 3.2. Вид «Все машины» (поповер)
- Табы провайдеров остаются. Внутри таба — список секций, по одной на машину.
- Шапка секции: точка статуса (онлайн/офлайн), имя машины, бейдж «сервер» у машины-сервера. **Тариф и пометки install/rotation остаются на карточках аккаунтов** (по usage-account-display.md) — в шапку не выносятся, иначе конфликт при нескольких аккаунтах на машине.
- Под шапкой — существующие карточки аккаунтов этой машины без изменений: окна, «Сброс: …· через …», цвета (< 80% синий, 80–94% жёлтый, ≥ 95% красный), planLabel, метки install/Out of rotation/Parked.
- Несколько аккаунтов на одной машине (Codex, Antigravity) — как сейчас, внутри секции своей машины.
- Строка-подсказка над списком: «Свободнее всего: **<машина>** — осталось N% по окну „<label>“». Правила расчёта (у окон нет id — только label, поэтому считаем по всем окнам):
  - участвуют машины **онлайн** (`connected`), у которых есть ≥1 аккаунт выбранного провайдера **в ротации**: `usage.status === "ok"` и `windows.length > 0`; аккаунты Out of rotation, Parked, Install unavailable не участвуют;
  - у каждой участницы берётся **максимальный % заполнения по всем окнам всех её аккаунтов в ротации** (машина с одним полным и одним пустым аккаунтом считается занятой);
  - свободнее та, у кого этот максимум минимален; `N = 100 − значение её худшего окна`, `<label>` — метка этого окна из ответа (`five-hour`/`Неделя`/… как пришло);
  - участниц меньше двух — строки нет.
- Состояния секции:
  - провайдер не авторизован → текст «не подключён» как в текущем пустом состоянии (signInHint; отдельной кнопки «Как подключить» в текущем UI нет — не добавляем);
  - провайдер `expired` → существующий expiredHint, как сейчас;
  - провайдер `not_installed` на этой машине → секция его не показывает вовсе (не «не подключён»): локальные провайдеры (acp-argon, agy) на удалённой машине не дают ложного пустого состояния;
  - машина офлайн → серая точка, «Машина недоступна · данные N мин назад», последние известные полосы приглушены (opacity ~0.55); данных нет — только текст;
  - ошибка сбора → существующее отображение ошибки аккаунта.
- Переключатель биллинга Claude (usage-pro-claude-key-toggle) управляет только сервером: в режиме «Все машины» рендерится **внутри секции машины-сервера** под её карточками; в режиме одной машины — как сейчас.
- Высота поповера фиксирована как сейчас (20rem), список прокручивается внутри.
- Обновление — существующей кнопкой в шапке поповера; отдельной нижней строки «Обновлено N с назад» нет (её нет и сейчас).

### 3.3. Мини-полосы машин у футера — ОПЦИЯ
- Новая настройка плагина `footerMachines` (boolean, **по умолчанию false**), подпись «Лимиты всех машин у футера», описание «Показывать рядом с закрытым футером мини-полосу каждой машины. Включайте, если в футере есть место». Механизм — как у `hideClaude` (секция настроек плагина, `useSettings()` + localStorage; в `server.ts` вызовов `bb.settings.define` нет и не нужен).
- Выключено → интерфейс как сейчас, без изменений.
- Включено и машин ≥ 2 → **плавающая пилюля у закрытого футера сайдбара** через `slots.experimental_appOverlay` (закрытая строка футера рендерится хостом — `kind:"disclosure"` отдаёт компонент только в раскрытую панель; встроить пилюлю в саму строку сегодняшний SDK не позволяет — см. §6): по каждой машине короткое имя, мини-полоса (26×5 px) и процент худшего окна выбранного провайдера, через разделитель. Имя длиннее 8 символов обрезается с многоточием, полное — в title.
- Позиционирование overlay-пилюли — у нижнего края сайдбара над футером; плагину принадлежат chrome, видимость и отзывчивость (сайдбар скрыт/узкий — пилюля скрывается).
- Ширина не должна ломать вёрстку при сайдбаре 260 px и экране 375 px: если не помещается — показывать только проценты без имён; совсем не помещается — скрыта.
- Выбранный провайдер — как в поповере; если дефолтный таб (`codex`) недоступен — первый доступный провайдер.

## 4. Данные
- «Все машины» вызывает существующий RPC `getUsage` с `machineIds` = все **настроенные не-ephemeral** машины (включая офлайн — офлайн отвечает ошибкой/статусом, секция рисует офлайн-состояние). Один запрос, ответы по машинам изолированы: ошибка одной не ломает другие.
- Форму ответа **расширяем по правилу двух схем** (PLUG-328 — правятся и серверная схема, и копия в `app.bundle.js`): в каждый элемент `machines[]` добавляются поля:
  - `server: boolean` — машина-сервер (для бейджа «сервер»; признак primary-хоста);
  - `ephemeral: boolean` — виртуальный/временный хост (исключается из счёта §3.1 и из `machineIds`);
  - `updatedAtMs: number | null` — время последнего успешного ответа машины (для «данные N мин назад» и состояния офлайн).
  Альтернативой не считаем клиентскую сборку этих фактов из других RPC — единый источник правды у сервера.
- Кэш и обновление — как сейчас (SWR; в поповере сайдбара интервал 120 с при видимой вкладке, в настройках 60 с — не меняем).

## 5. Файлы
- `plugins/bb-plugin-usage-pro/app.bundle.js` — интерфейс (исходника нет, правки прямо в бандле, как в прошлых задачах), `app.css` — стили.
- `plugins/bb-plugin-usage-pro/server.ts` — схема `getUsage` (новые поля `server`/`ephemeral`/`updatedAtMs` в `machines[]`, §4) и их наполнение; `footerMachines` — фронтовая настройка секции (как `hideClaude`), сервер не трогает.
- Тесты рядом (`*.test.ts`, vitest): расчёт строки «Свободнее всего», видимость пункта «Все машины» (1 и 2 машины), overlay-пилюля при `footerMachines` false/true, изоляция ошибки одной машины.
- Документы: этот файл → `docs/specs/usage-pro-all-machines.md`, раздел в `plugins/bb-plugin-usage-pro/README.md`.

## 6. Не делаем
- Новый плагин — нет, только Usage Pro.
- Суммирование лимитов разных аккаунтов — нет.
- Изменение логики сбора на машинах (Codex, agy, Claude) — нет.
- Пилюля **внутри** закрытой строки футера — нет: сегодняшний SDK рендерит закрытую строку хостом (icon+label), плагинный компонент disclosure живёт только в раскрытой панели. Нужен хост-API (напр. `closedComponent` у disclosure-регистрации) — отдельная задача на bb-app, вне этого релиза. Опция §3.3 реализована overlay-пилюлей у футера.
