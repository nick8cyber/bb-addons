# Usage Pro — лимиты всех машин сразу

## 1. Зачем
У клиента два сервера в одном BB: `main` (сервер) и `worker` (воркер), на каждом свой аккаунт Claude. Сейчас панель лимитов показывает одну машину за раз через меню «Usage source». Нужно видеть лимиты всех машин одновременно, чтобы понимать, куда отправлять тяжёлые треды.

## 2. Главное правило (не обсуждается)
Лимиты машины запрашивает **сама эта машина** — через её демон, как сейчас делает `getUsage` (сбор идёт через RPC `provider-usage.v1.listResources` / `getResource` плагинов-источников на хосте). Сервер не читает чужие файлы с ключами и не ходит в API провайдера за другую машину. IP запросов к Anthropic не смешиваются.

Проверено 25.11 на клиенте: при `getUsage` по `worker` соединения к Anthropic идут только с `worker` (uid 1000), с `main` — ни одного.

## 3. Что видит пользователь

### 3.1. Меню «Usage source»
- Новый первый пункт **«Все машины»**, под ним разделитель и машины, как сейчас.
- Пункт есть, только если **настроенных** машин ≥ 2. «Настроенные» — не-ephemeral хосты из списка машин BB, исключая синтетические `source:<pluginId>`, — **независимо от онлайн-статуса и от `providers.length` на холодном старте** (офлайн-машина после перезагрузки может отдать `providers: []`, она всё равно считается и показывает офлайн-состояние §3.2). Одна машина — интерфейс как сейчас, без изменений.
- При ≥ 2 машинах «Все машины» выбрано по умолчанию. Выбор пользователя запоминается так же, как сейчас запоминается машина — **в памяти сессии, без персистентности** (как сейчас: при перезагрузке сбрасывается на дефолт).
- Меню есть в двух местах — поповер сайдбара и раздел настроек плагина; пункт «Все машины» есть в обоих. Раскладка в настройках отличается от поповера (там нет табов провайдеров — сейчас все провайдеры одной машины идут вертикальным списком): в режиме «Все машины» группировка **«машина → провайдеры»** — секция машины (та же шапка §3.2), внутри её провайдеры вертикально как сейчас; строка «Свободнее всего» в настройках **не показывается** (нет выбранного таба-провайдера); офлайн-машины в меню `Mm` **не disabled** — выбираются и показывают офлайн-секцию; загрузка `Vm` — запрос по всем `machineIds` одним вызовом (§4), не цикл по одной connected.
- Если ранее выбранный провайдер-таб недоступен (нет такого провайдера ни на одной машине, напр. дефолтный `codex` при установке только с Claude) — выбирается первый доступный провайдер.

### 3.2. Вид «Все машины» (поповер)
- Табы провайдеров остаются. Внутри таба — список секций, по одной на машину.
- Шапка секции: точка статуса (онлайн/офлайн), имя машины, бейдж «сервер» у машины-сервера. **Тариф и пометки install/rotation остаются на карточках аккаунтов** (по usage-account-display.md) — в шапку не выносятся, иначе конфликт при нескольких аккаунтах на машине.
- Под шапкой — существующие карточки аккаунтов этой машины без изменений: окна, «Сброс: …· через …», цвета (< 80% синий, 80–94% жёлтый, ≥ 95% красный), planLabel, метки install/Out of rotation/Parked.
- Несколько аккаунтов на одной машине (Codex, Antigravity) — как сейчас, внутри секции своей машины.
- Строка-подсказка над списком: «Свободнее всего: **<машина>** — осталось N% по окну „<label>“». Правила расчёта (у окон нет id — только label, поэтому считаем по всем окнам):
  - участвуют машины **онлайн** (`connected`), у которых есть ≥1 аккаунт выбранного провайдера **в ротации**: `usage.status === "ok"` и `windows.length > 0`; аккаунты исключаются по `planLabel` — `Out of rotation`, префиксы `Parked:` и `Install unavailable:` (отдельного флага ротации в схеме нет);
  - на табе `agy` учитывается фильтр `hideClaudeModels` — скрытые аккаунты в расчёт не берутся (как в существующем списке);
  - у каждой участницы берётся **максимальный % заполнения по всем окнам всех её аккаунтов в ротации** (машина с одним полным и одним пустым аккаунтом считается занятой);
  - свободнее та, у кого этот максимум минимален; `N = Math.max(0, Math.round(100 − max))`; ничья — выигрывает первая в порядке списка (сервер идёт первым); `<label>` — `formatWindowLabel` этого окна (как в макете «Неделя», не сырой id);
  - участниц меньше двух — строки нет.
- Состояния секции:
  - провайдер не авторизован → текст «не подключён» как в текущем пустом состоянии (signInHint; отдельной кнопки «Как подключить» в текущем UI нет — не добавляем);
  - провайдер `expired` → существующий expiredHint, как сейчас;
  - у машины **нет ни одной записи** выбранного провайдера (`machine.providers` без этого `providerId` — включая `not_installed` и «провайдер только у сервера») → секция его не показывает вовсе (не «не подключён»): локальные провайдеры (acp-argon, agy — §4) на удалённой машине не дают ложного пустого состояния;
  - машина офлайн → серая точка, «Машина недоступна · данные N мин назад», последние известные полосы приглушены (opacity ~0.55); данных нет — только текст;
  - ошибка сбора → существующее отображение ошибки аккаунта.
- Переключатель биллинга Claude (usage-pro-claude-key-toggle) управляет только сервером: в режиме «Все машины» рендерится **внутри секции машины-сервера** под её карточками; в режиме одной машины — как сейчас.
- Высота поповера фиксирована как сейчас (20rem), список прокручивается внутри.
- Обновление — существующей кнопкой в шапке поповера; отдельной нижней строки «Обновлено N с назад» нет (её нет и сейчас).

### 3.3. Мини-полосы машин у футера — ОПЦИЯ
- Новая настройка плагина `footerMachines` (boolean, **по умолчанию false**), подпись «Лимиты всех машин у футера», описание «Показывать в футере мини-полосу каждой машины. Включайте, если в футере есть место». Механизм — как у `hideClaudeModels`: `bb.settings.define` в `dist/provider-usage-base.js` + чтение во фронте через `useSettings().values.footerMachines` (localStorage — фолбэк приоритета ниже SDK-настройки, как у `useHideClaude()`).
- Выключено → интерфейс как сейчас, без изменений.
- Включено и машин ≥ 2 → **полоса в ряду иконок закрытого футера сайдбара** через `slots.experimental_appOverlay` (закрытая строка футера рендерится хостом — `kind:"disclosure"` отдаёт компонент только в раскрытую панель; встроить элементы в сам хостовый ряд сегодняшний SDK не позволяет — см. §6): overlay-полоса позиционируется **визуально в конец ряда иконок футера** — по каждой машине короткое имя, мини-полоса (26×5 px) и процент худшего окна выбранного провайдера, через разделитель. Имя длиннее 8 символов обрезается с многоточием, полное — в title.
- Позиционирование — привязка к правому краю футерного ряда (у клиента кнопка звонка уходит в левую панель, место освобождается — live-call-button-placement); плагину принадлежат chrome, видимость и отзывчивость (сайдбар скрыт/узкий — полоса скрывается).
- Ширина проверяется на сайдбаре **260 px** и экране 375 px: если не помещается в ряд — показывать только проценты без имён; совсем не помещается — скрыта.
- Полоса скрывается, когда открыт поповер Usage Pro (не перекрывает 20rem-панель). Клик по полосе — открывает тот же поповер (disclosure). Офлайн-машина в полосе — её мини-полоса приглушена (как полосы §3.2) по последним данным `updatedAtMs`; данных нет — прочерк.
- Выбранный провайдер — как в поповере; если дефолтный таб (`codex`) недоступен — первый доступный провайдер; на табе `agy` худшее окно считается с фильтром `hideClaudeModels` (§3.2).

## 4. Данные
- «Все машины» вызывает существующий RPC `getUsage` с `machineIds` = все **настроенные не-ephemeral** машины (включая офлайн — офлайн отвечает ошибкой/статусом, секция рисует офлайн-состояние). Один запрос, ответы по машинам изолированы: ошибка одной не ломает другие.
- Форму ответа **расширяем по правилу двух схем** (PLUG-328 — правятся и серверная схема в `dist/provider-usage-base.js`, и копия в `app.bundle.js`; `server.ts` — тонкая обёртка-реэкспорт, её не трогаем): в каждый элемент `machines[]` добавляются поля:
  - `server: boolean` — машина-сервер (для бейджа «сервер»; признак `machine.id === primaryHostId`);
  - `updatedAtMs: number | null` — метка **последнего успешного ответа этой машины** (для «данные N мин назад» и состояния офлайн). Это отдельное поле, **не** `loadedAt`: не сбрасывается `markDirty()` и не очищается при временном исчезновении ресурса из `listResources`. Сервер хранит его на кэше машины и отдаёт вместе с последними известными `providers` — именно из этого кэша секция офлайн-машины рисует приглушённые полосы §3.2.
  Поле `ephemeral` **не добавляем**: `readUsage` уже отбрасывает `host.type === "ephemeral"` из `bb.sdk.hosts.list()`, а синтетические элементы `source:<pluginId>` фронт отличает по префиксу `source:` в `id` — дополнительный флаг не нужен.
- Метаданные провайдеров в `readUsage` сейчас запрашиваются по `machineIds?.find(id => !id.startsWith("source:"))` — только первой машине. При мультимашинном запросе метаданные (displayName/logoUrl/icon/signInHint) должны собираться по всем запрошенным хостам (или без сужения), иначе у не-primary машин фолбэчные имена/лого.
- Локальные провайдеры только у сервера: `acp-argon` уже добавляется только для `primaryHostId`; **`agy` сейчас добавляется всем машинам без `source:` — сузить до `primaryHostId`** (иначе локальные аккаунты agy сервера дублируются на удалённой машине со статусом ok и исказят «Свободнее всего»; согласовать с `usage-integration.test.ts:870`).
- Кэш и обновление — как сейчас (SWR; в поповере сайдбара интервал 120 с при видимой вкладке, в настройках 60 с — не меняем).

## 5. Файлы
- `plugins/bb-plugin-usage-pro/app.bundle.js` — интерфейс (исходника нет, правки прямо в бандле, как в прошлых задачах), `app.css` — стили.
- `plugins/bb-plugin-usage-pro/dist/provider-usage-base.js` — реализация серверной части (`server.ts` — 14-строчная обёртка-реэкспорт, её не правим): схема `usageMachineSchema` и контракт `providerUsageRpcContract` (+`server`/`updatedAtMs` в `machines[]`, §4), наполнение в `readUsage` (метаданные по всем хостам, `agy` только `primaryHostId`, метка `updatedAtMs` на кэше машины), `bb.settings.define` → `footerMachines`; при необходимости `dist/provider-usage-base.d.ts`.
- Тесты рядом (`*.test.ts`, vitest): расчёт строки «Свободнее всего» (включая исключения по planLabel, ничью и кламп), видимость пункта «Все машины» (1 и 2 машины, офлайн с пустым providers), полоса при `footerMachines` false/true, изоляция ошибки одной машины; **расширить `usage-app-schema.test.ts`** — сейчас сверяет только ключи ok-ветки `providerUsageSchema`, добавить сверку `usageMachineSchema` с копией в `app.bundle.js` (правило двух схем).
- Документы: этот файл → `docs/specs/usage-pro-all-machines.md`, раздел в `plugins/bb-plugin-usage-pro/README.md`.

## 6. Не делаем
- Новый плагин — нет, только Usage Pro.
- Суммирование лимитов разных аккаунтов — нет.
- Изменение логики сбора на машинах (Codex, agy, Claude) — нет.
- Пилюля **внутри** закрытой строки футера — нет: сегодняшний SDK рендерит закрытую строку хостом (icon+label), плагинный компонент disclosure живёт только в раскрытой панели. Нужен хост-API (напр. `closedComponent` у disclosure-регистрации) — отдельная задача на bb-app, вне этого релиза. Опция §3.3 реализована overlay-пилюлей у футера.
