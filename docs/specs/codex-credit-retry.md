# Дополнение Provider usage (Pro)

Владелец поручил самостоятельно восстановить автоповтор для ошибки out of credits. Ядро BB и встроенный provider-retry не менять; добавить обработчик turn.failed в существующий usage-pro. Не создавать отдельный плагин и не менять аккаунты/модели/маршрутизацию.

## Контракт

Обрабатывать только Codex, category rate-limit, rateLimits.kind=credits/status=blocked/reachedReason=workspace_member_credits_depleted. Это подтверждённый структурированный эквивалент наблюдавшегося сообщения; не искать out of credits в пользовательском тексте и не повторять произвольные финансовые/авторизационные ошибки.

Без reset — интервалы 15, 30, 60, 120 минут по attemptNumber 1–4 плюс jitter 0–30 секунд. После пятой неудачи остановиться. Повтор — sdk.threads.retry по requestId, не копия сообщения; обычная durable очередь BB с отменой. Никаких собственных setTimeout и опроса аккаунтов.

Pool-routed отказы оставить встроенному retry: определить через публичный availability RPC, при найденном маршруте/ошибке RPC не обходить его политику. Перед записью проверить thread error/Codex/not archived. Не вмешиваться в активные, остановленные, архивные треды или пользовательские сообщения.

### Совместимость с очередью (исправление 27 октября)

Подтверждён отказ `queue-not-empty`: обработчик пропускал ошибку из-за любого сообщения в очереди, включая отложенное. Это не ошибка распознавания строки: последние ошибки этого треда также успешно получали повторы в 07:15 и 07:45 UTC. Встроенный retry отдельно пишет `not-resettable` — это не диагностика нашего обработчика.

Разрешить постановку retry рядом с существующей очередью ТОЛЬКО если каждая запись — обычный `payload.kind=inline`, `state=scheduled`, `waitingOn.kind=time`, конечный `sendAt` строго позже вычисленного времени retry, `groupWithNext=false`. Ни текст, ни время, ни порядок этих сообщений не менять. Готовый ввод, более ранний/одновременный ввод, любой retry, группировка, claimed/failed/waiting/неизвестное состояние блокируют постановку. Перед самим SDK retry повторно прочитать очередь и состояние треда: асинхронная проверка pool не должна обходить появившийся ввод или ручной stop. Core повторно проверяет актуальность failed request и дубли цепочки.

Не перезапускать прежние чужие треды при установке и не переносить их запланированные продолжения. Проверить обработку и реальную очередь в изолированном fake-host/core harness без production-сбоев модели.

Ошибка `workspace_member_credits_depleted` не доказывает денежное состояние подписки. Текст очереди — «Временный отказ Codex — автоматический повтор»; названия и описания плагина/README не заявляют реальное исчерпание денег. Причины отказа записывать в диагностике и журнале. Исключение SDK при планировании должно записать declined/scheduling-error, не оставлять предыдущий scheduled как последнее решение.

Одновременно обрабатывать requestId+attemptNumber один раз. Хранить успешное планирование в KV, чтобы дубли и повторная доставка после отмены/перезагрузки не создавали новый retry. Core также защищает единственную живую retry-запись. Не сканировать и не перезапускать старые неудачи при загрузке плагина.

## Сохранение существующего поведения

Оригинальный уже скомпилированный backend usage-pro перенести без изменения логики в vendor/provider-usage-base.js; server.ts вызывает его и регистрирует дополнительный обработчик. Существующие RPC, настройки hideClaudeModels, collectors и frontend не менять. Сравнить готовые app.js/app.css с текущими live-байтами. Исходный dirty worktree не трогать; постоянная отдельная ветка/worktree.

## Проверки

Unit + официальный SDK fake host: реальная форма ошибки, четыре попытки и cap, обычный лимит/overload/auth/другой provider/reason — не трогать; pool ready/blocked/unavailable/failed — пропуск; duplicate/concurrent/reload/cancel; ручное вмешательство/архив/новая очередь; SDK retry rejection; сохранение диагностик; регистрация и dispose. Добавить будущую scheduled inline очередь, границы времени, несколько строк, retry/grouped/failed/claimed/interaction waiting, изменение очереди/статуса между проверками; строки не мутируются. `npm ci && npm test && npm run typecheck && bb plugin build .`, затем `git diff --check` от нового документного коммита.

Build/typecheck/diff check, install того же usage-pro из постоянной worktree, проверить running, старые настройки и getUsage RPC, неизменность frontend, публичную read-only диагностику creditRetry.status. Не вызывать искусственную ошибку или неудачный запрос модели на production и не повторять старый активный тред ради теста. Полный queue путь проверить в изолированном harness.

После проверки Advisor один раз; коммит/push в отдельную feature-ветку bb-addons. Без main/PR/BB restart и без сообщений/остановки чужих тредов.
