# pi-gateways — шлюзы внешних моделей через pi

Статус: принято и реализовано. Плагин `plugins/bb-plugin-pi-gateways`.

## 1. Назначение

Плагин подключает внешние каталоги моделей к встроенному в BB агенту `pi` через стандартные HTTP API:

- **Готовые пресеты**: Google AI Studio (Gemini), TokenRouter, OpenRouter, NVIDIA Build, Radeon Cloud.
- **Встроенные CLI-источники**: бесплатные модели OpenCode Zen и Kilo Code без запуска тяжелых ACP-мостов (экономия ~650 МБ RAM на тред, до 1.3 ГБ за два треда).
- **Пользовательские эндпоинты (Custom)**: любые шлюзы с поддержкой `openai-completions`, `openai-responses`, `anthropic-messages` или `google-generative-ai`.
- **Управление каталогом `models.json`**: бесконфликтное слияние с сохранением чужих записей, резервное копирование, адаптация (adoption) и удаление сторонних блоков.
- **Интерфейс настроек и CLI**: секция настроек в BB Settings с проверкой соединения (probe) и выбором моделей, а также консольная утилита `bb pi-gateways`.

## 2. Архитектура и модель данных

### 2.1. Принцип работы без тяжелых мостов
В отличие от провайдеров `acp-opencode` и `acp-kilo`, запускающих отдельный процесс Node.js на каждый тред, агент `pi` встроен непосредственно в демон BB. Он считывает каталог моделей из файла `~/.pi/agent/models.json`. Плагин конфигурирует этот файл, направляя `pi` напрямую к HTTP-шлюзам.

### 2.2. Безопасность ключей (Key References)
Значения секретных токенов **никогда не сохраняются на диск** в открытом виде:
- В манифест плагина (`<dataDir>/custom-endpoints.json` в хостовой директории данных) записывается только источник ключа: переменная окружения (`env`), путь к файлу (`file`) или команда (`command`).
- В `models.json` записывается синтаксис ссылок, понятный самому `pi`:
  - `!команда` (например, вызов легковесного reader-скрипта);
  - `$VAR_NAME` (чтение из переменной окружения при старте сессии pi).
- Ротация токена в исходном CLI или `.env` не требует повторной перезаписи конфигурации.
- Проверка ключа (`resolveKeyRefValue` в `src/keyref.ts`) эмулирует поведение `pi`: таймаут 10 секунд, запуск строго через `/bin/sh`, обрезка пробелов.

### 2.3. Читатели учетных данных (Credential Readers)
Для встроенных шлюзов плагин устанавливает исполняемые скрипты в `<dataDir>/readers/` с правами `0700`:
- `read-zen.mjs`: считывает токен OpenCode из `~/.local/share/opencode/auth.json` (`opencode.key`).
- `read-kilo.mjs`: считывает токен Kilo Code из SQLite-базы `~/.local/share/kilo/kilo.db` (`credential` table, `integration_id = 'kilo'`) в режиме строгого чтения (`mode=ro` через `node:sqlite` или утилиту `sqlite3`).

### 2.4. Политики ценообразования и отбор моделей
- `gateway-default`: поведение по умолчанию для шлюзов (кроме `google-generative-ai`). При отсутствии блока цен `pricing` модель считается доступной/бесплатной по правам учетной записи (как у OpenCode Zen и Kilo Code). При наличии блока цен проверяется их строгое равенство нулю (`pricing.prompt === 0 && pricing.completion === 0`).
- `catalogue`: шлюз возвращает стоимость в каталоге (например, OpenRouter, TokenRouter). Автоматически отбираются модели со строго нулевой ценой (`pricing.prompt === 0 && pricing.completion === 0`). Модели без блока цен бесплатными не считаются.
- `unknown`: шлюз не гарантирует передачу цен в каталоге (Google AI Studio, NVIDIA Build, Radeon Cloud). Автоматический выбор «всех бесплатных» запрещен (`requiresExplicitModels: true`); сохранение требует явного указания списка идентификаторов моделей пользователем (`selectionMode: "explicit"`).

### 2.5. Защита зарезервированных идентификаторов (Reserved IDs)
При старте плагин формирует список зарезервированных системных провайдеров (`discoverReservedProviderIds`, RPC `reservedIds`):
- Динамически зарезервированные системные ID (`DYNAMIC_RESERVED_IDS = ["radius"]`): провайдеры, которые `pi` инстанцирует динамически в рантайме без статического файла каталога.
- Статические системные провайдеры: каталог `@earendil-works/pi-ai/dist/providers/data/*.json` на диске (`locatePiProvidersData` в `src/custom.ts:196-206`, поиск вложенного в `@earendil-works/pi-coding-agent` или захойщенного пакета `@earendil-works/pi-ai`), поставляющий системные каталоги «из коробки» (`anthropic`, `openai`, `google`, `groq` и др.).
- Защита от коллизий: использование любого зарезервированного ID для пользовательского шлюза блокируется, чтобы `pi` не подмешал свой жестко зашитый каталог. При невозможности обнаружения каталога системных провайдеров сохранение блокируется (fail-closed).

### 2.6. Модель владения (Ownership)
Каждый блок в `models.json` классифицируется:
- `builtin`: встроенные шлюзы плагина (`opencode-zen`, `kilo`).
- `owned`: шлюзы, созданные плагином и зафиксированные в манифесте.
- `adopted`: сторонние блоки `models.json`, взятые под управление плагином.
- `foreign`: сторонние блоки, созданные другими инструментами (только чтение).
- `orphaned`: блоки, числящиеся в манифесте, но отсутствующие в `models.json`.
- `reserved`: встроенные системные провайдеры самого `pi`.
- Признак `drifted`: внешний блок изменился в `models.json` в обход плагина после адаптации.

## 3. Хранилище, файлы и синхронизация

- **Основной файл**: `~/.pi/agent/models.json` на целевом хосте BB.
- **Манифест плагина**: `<dataDir>/custom-endpoints.json` — хранит структурированные описания кастомных эндпоинтов, привязку к пресетам, источники ключей и хеши содержимого (`contentHash`) для отслеживания дрейфа.
- **Атомарная запись**: запись выполняется через временный файл с последующим `renameSync`.
- **Резервные копии**: перед каждой модификацией создается снимок `models.json.bak-pi-gateways-YYYYMMDD-HHMMSSmmm`. Хранятся последние 10 копий, старые ротируются автоматически.
- **Защита от гонок**: операции с файлом сериализуются через очередь промисов хостового воркера. Перед записью сверяется хеш файла: если сторонний процесс изменил файл, изменение плагина накатывается поверх свежего содержимого.

## 4. UI-интеграция

- Секция настроек регистрируется через слот `app.slots.settingsSection`:
  - Идентификатор: `pi-gateways`.
  - Заголовок: `Pi Gateways`.
  - Компонент: `PiGatewaysSection` (`src/PiGatewaysSection.tsx`).
- Селектор хоста (Host picker) отображается при наличии нескольких зарегистрированных хостов BB.
- Карточки статуса встроенных шлюзов (OpenCode Zen, Kilo Code) с индикацией найденных учетных данных, числа моделей и ошибок.
- Каталог пресетов с кнопкой быстрого добавления (Google AI Studio, TokenRouter, OpenRouter, NVIDIA Build, Radeon Cloud).
- Диалог добавления/редактирования эндпоинта: ввод URL, выбор типа API, источника ключа (переменная окружения, файл, команда), кнопка проверки соединения («Test connection / Probe»).
- Модальное окно выбора моделей: фильтрация по поисковой строке, переключение «Все бесплатные» / «Только выбранные», предупреждения о не верифицированных моделях.
- Список сторонних провайдеров с кнопками «Adopt» (взять под управление) и «Delete» (принудительное удаление).

## 5. Серверные методы (RPC) и CLI

### 5.1. RPC-контракт (`rpcSchemas`)
- `status`: проверка наличия файлов конфигурации и статуса встроенных шлюзов.
- `refresh`: обновление конфигурации встроенных шлюзов в `models.json`.
- `remove`: удаление записей встроенных шлюзов из `models.json`.
- `reservedIds`: получение списка системных ID провайдеров `pi`.
- `probe`: проверка доступности эндпоинта, валидация ключа и загрузка каталога моделей.
- `saveCustom`: сохранение нового провайдера (валидация, проверка на коллизии, запись в манифест и `models.json`).
- `updateCustom`: изменение настроек существующего кастомного шлюза.
- `refreshCustom` / `refresh`: актуализация каталогов моделей по сети.
- `deleteCustom` / `deleteProvider`: удаление блока из `models.json` (с флагом `force` для сторонних и `disownOnly` для снятия с учета).
- `listCustom` / `listProviders`: получение списка всех шлюзов с метаданными и статусом владения.
- `providerDetail`: детальная информация по конкретному провайдеру.
- `adopt` / `disown`: взятие стороннего блока под управление или снятие с учета.
- `hosts`: список доступных хостов BB.

### 5.2. Консольный интерфейс `bb pi-gateways`
- `bb pi-gateways status [--host ID]`: состояние `models.json` и найденных учетных записей.
- `bb pi-gateways presets`: список доступных пресетов и их переменных окружения.
- `bb pi-gateways list [--json] [--host ID]`: группированный список (Built-in, Managed, Unmanaged).
- `bb pi-gateways show <id> [--host ID]`: детальный отчет по провайдеру, моделям и источнику ключа.
- `bb pi-gateways test [--preset NAME | --base-url URL --api KIND] [--key-* ...]`: пробный запрос и проверка моделей.
- `bb pi-gateways add [--preset NAME] [--models id1,id2] [--key-* ...]`: сохранение шлюза.
- `bb pi-gateways edit <id> [--name N] [--models a,b]`: редактирование шлюза.
- `bb pi-gateways refresh [--only ID]`: обновление встроенных шлюзов.
- `bb pi-gateways refresh-endpoints [--only ID] [--accept-drift]`: обновление каталогов кастомных шлюзов.
- `bb pi-gateways adopt <id> [--key-env NAME]`: взять существующий блок под управление.
- `bb pi-gateways disown <id>`: прекратить управление блоком без его удаления.
- `bb pi-gateways delete <id> [--force]`: удалить блок из `models.json`.
- `bb pi-gateways remove`: удалить все записи плагина из `models.json`.

## 6. Конфигурация и окружение

- Переменные окружения по умолчанию для пресетов:
  - Google AI Studio: `GEMINI_API_KEY`.
  - TokenRouter: `TOKENROUTER_API_KEY`.
  - OpenRouter: `OPENROUTER_API_KEY`.
  - NVIDIA Build: `NVIDIA_API_KEY`.
  - Radeon Cloud: `RADEON_API_KEY`.
- Поддерживаемые протоколы API (`ApiKind`):
  - `openai-completions` (OpenAI-совместимый эндпоинт чат-комплишенов `/chat/completions`, каталог `/models`).
  - `openai-responses` (OpenAI Responses API).
  - `anthropic-messages` (Anthropic-совместимый эндпоинт сообщений `/v1/messages`).
  - `google-generative-ai` (Google AI Studio API `/models`).

- **Типизация**: `npm run typecheck` (`tsc --noEmit`).
- **Тесты**: запуск через Node.js test runner со стриппингом типов:
  ```bash
  node --experimental-strip-types --import ./tests/ts-resolver.mjs --test tests/*.test.ts
  ```

  Покрывают:
  - `adoption.test.ts`: сценарии адаптации сторонних записей и отслеживание дрейфа.

  - `manifest.test.ts`: сериализация и миграции манифеста.
  - `merge-preserve.test.ts`: бесконфликтное слияние с сохранением чужих записей в `models.json`.
  - `provider-presets.test.ts`: конфигурации пресетов и сопоставление моделей.
  - `refresh-tolerance.test.ts`: обработка сетевых сбоев при обновлении каталогов.
  - `write-race.test.ts`: защита от гонок параллельных записей.

## 8. Известные ограничения и граничные случаи

- **Кэширование воркерами pi**: запущенные сессии и фоновые воркеры `pi` считывают `models.json` один раз при старте. Изменения каталога становятся доступны в активных сессиях только после перезапуска демона BB (`systemctl --user restart bb.service`) при отсутствии выполняющихся шагов.
- **Мультихостовость**: файл `models.json` физически расположен на конкретном хосте. В конфигурациях с несколькими машинами операции требуют указания флага `--host` или выбора хоста в UI.
- **Строгая типизация цен Google**: каталог Google AI Studio не передает данные о ценах, поэтому плагин принципиально запрещает автовыбор «все бесплатные» для Gemini — список моделей должен выбираться явно.
