# Изоляция данных и исполнение в песочнице (Zero-Leak Sandbox)

> [!IMPORTANT] Нормативный статус
> Документ развивает требования [ADR-0035](../adr/0035-orchestrator-zero-leak-sandbox.md), устраняет 5 критических блокеров независимого аудита безопасности (`audit-zero-leak-argon.md`) и регламентирует безопасное подключение публичных и бесплатных моделей (OpenCode free, веб-Gemini/Argon) в оркестратор.

---

## 1. Термины и область действия

- **Zero-Leak Sandbox:** комплексная подсистема изоляции данных и процессов, исключающая передачу конфиденциального кода, системных путей, учетных записей и истории репозитория сторонним провайдерам.
- **Snapshot Sandbox:** одноразовая среда рабочей копии, создаваемая из архива целевого коммита (`git archive`), полностью лишённая связи с родительским репозиторием `.git` хоста.
- **DLP Redaction Engine:** детерминированный модуль маскирования чувствительных сущностей во входных данных (промпты, диффы, вложения) и контролируемой подстановки в выходных результатах.
- **Unmasking Oracle Attack:** класс атак, при котором злоумышленник через prompt injection или специально сформированные тесты провоцирует модель вернуть токен секрета в публичном фрагменте ответа, в результате чего наивный модуль демаскирования заменяет его на реальный секрет и запекает в коммит.
- **Route Trust Level (`route.trust`):** уровень доверия маршрута (`trusted-local`, `trusted-cloud`, `public`), определяющий допустимость работы с конфиденциальными файлами и глубину изоляции рантайма.

## 2. Модель угроз и векторы утечек

| Вектор утечки | Механизм в наивной схеме | Решение Zero-Leak Sandbox |
|---|---|---|
| **Git Object Store & History** | `git worktree` хранит ссылку на общий `.git`. Агент вызывает `git log -p --all`, `git reflog`, `git rev-list --objects`, читая удалённые секреты, конфиденциальные файлы и метаданные авторов (`git log --format="%an %ae"`). | **Snapshot Sandbox:** разворачивание чистого tar-слепка (`git archive`) в изолированный каталог с одноразовым `git init`. Физическое отсутствие родительского `.git`. |
| **Runtime Traversal `confidentialPaths`** | `confidentialPaths` проверяется только на старте. Во время выполнения агент читает файлы секретных модулей напрямую через `read_file` или `bash`. | **Mount Masking & Archive Exclusion:** файлы `confidentialPaths` исключаются из архива слепка и принудительно маскируются пустыми точками монтирования `--ro-bind /dev/null`. |
| **Кэши, артефакты и симлинки** | `.npmrc`, `.yarnrc.yml`, `pip.conf` содержат токены реестров. Дампы `.pytest_cache`, `.next`, `node_modules/.cache` хранят дампы памяти и пути хоста. Симлинки (`ln -s /etc/passwd`) обходят проверки. | **Ephemeral tmpfs & Scrubbing:** чистка конфигов пакетных менеджеров в слепке, монтирование `/tmp` в оперативной памяти, запрет разыменования симлинков за пределами `/workspace`. |
| **Синтаксический слом масками** | Кириллические скобочные маркеры `[скрыто: secret]` ломают парсеры JSON/YAML/URL, компиляторы и сходимость `git apply`. | **RFC-совместимые ASCII-псевдонимы:** стандартизированные идентификаторы (`host-N.bb-mask.internal`, `198.51.100.N`), сохраняющие валидность AST и парсеров. |
| **Unmasking Oracle** | Слепая замена токенов секретов на реальные значения во всём выходном тексте и диффе. | **One-Way Context Unmasking:** секреты подставляются ТОЛЬКО в неизменённые контекстные строки диффа. Запрет появления секретов в добавленных строках `+` и отчётах. |
| **Утечки окружения и DoS хоста** | Неограниченный `bash` агента видит процессы хоста (`/proc`), системные сокеты (`SSH_AUTH_SOCK`, Docker) и может запустить fork-бомбу. | **Bubblewrap + cgroups v2:** `--unshare-all`, `--die-with-parent`, скрытый `/proc`, закрытые сокеты, сетевой карантин `--unshare-net`, лимиты `RLIMIT_NPROC` и памяти. |

## 3. Архитектура песочницы Snapshot Sandbox

### 3.1. Жизненный цикл одноразового слепка

1. **Создание слепка:**
   - Для задачи с базовым коммитом `<base-sha>` оркестратор генерирует временный каталог песочницы:
     `SANDBOX_DIR="/tmp/bb-sandbox-${taskKey}-${runId}"`
   - Извлекается чистый архив ревизии без служебных файлов `.git`:
     `git archive --format=tar <base-sha> | tar -xf - -C "$SANDBOX_DIR"`
   - Файлы, подпадающие под `confidentialPaths`, удаляются из каталога `$SANDBOX_DIR` до запуска процессов.
   - Выполняется предварительная очистка артефактов и конфигов: удаляются `.env*`, зачищаются токены из `.npmrc`, удаляются `.git`, `.pytest_cache`, `.mypy_cache`.

2. **Инициализация одноразового Git:**
   - Внутри `$SANDBOX_DIR` выполняется:
     ```bash
     git -C "$SANDBOX_DIR" init -q
     git -C "$SANDBOX_DIR" config user.name "BB Sandbox Agent"
     git -C "$SANDBOX_DIR" config user.email "sandbox@localhost"
     git -C "$SANDBOX_DIR" add -A
     git -C "$SANDBOX_DIR" commit -q -m "sandbox root snapshot"
     ```
   - Репозиторий песочницы содержит ровно одну ревизию. Команды инспекции истории безопасны.

3. **Запуск агента в песочнице Bubblewrap:**
   - Агент и его дочерние инструменты запускаются внутри изолированного окружения:
     ```bash
     bwrap \
       --unshare-all \
       --die-with-parent \
       --ro-bind /usr /usr \
       --ro-bind /bin /bin \
       --ro-bind /lib /lib \
       --ro-bind /lib64 /lib64 \
       --ro-bind /etc/alternatives /etc/alternatives \
       --ro-bind /etc/resolv.conf /etc/resolv.conf \
       --proc /proc \
       --dev /dev \
       --tmpfs /tmp \
       --tmpfs /var/tmp \
       --bind "$SANDBOX_DIR" /workspace \
       --chdir /workspace \
       --unshare-net \
       --setenv HOME /tmp \
       --setenv PATH /usr/local/bin:/usr/bin:/bin \
       --setenv BB_SANDBOX "1" \
       -- <команда_агента>
     ```
   - Для путей `confidentialPaths` добавляются перекрытия:
     `--ro-bind /dev/null /workspace/<confidentialPath>`

4. **Извлечение и применение результата:**
   - По завершении хода оркестратор снимает дифф:
     `git -C "$SANDBOX_DIR" diff HEAD > "$SANDBOX_DIR/patch.diff"`
   - Дифф валидируется через Diff DLP Unmasker.
   - Валидированный патч применяется к рабочему дереву задачи в доверенном контуре:
     `git apply --check "$SANDBOX_DIR/patch.diff" && git apply "$SANDBOX_DIR/patch.diff"`
   - Каталог `$SANDBOX_DIR` безопасно удаляется:
     `rm -rf "$SANDBOX_DIR"`

## 4. Спецификация DLP Redaction Engine

### 4.1. Стандартизированный синтаксис масок (RFC ASCII)

Все замены выполняются детерминированно с ведением локальной таблицы соответствий задачи (`DLP_MAP`):

1. **Хосты и домены:**
   - Шаблон замены: `host-${N}.bb-mask.internal` (где N — порядковый номер уникального хоста в контексте задачи).
   - Поддерживает обратную двустороннюю подстановку. Не ломает парсеры URL и сетевые модули.

2. **IPv4-адреса:**
   - Шаблон замены: `198.51.100.${N}` (выделенный диапазон документации RFC 5737 TEST-NET-2).
   - Поддерживает обратную двустороннюю подстановку. Проходит валидацию встроенных библиотек `net.isIP()`, regex и валидаторов конфигураций.

3. **Идентификаторы тредов и задач:**
   - Шаблон замены: `thr_MASKED_${NNN}`, `TASK_MASKED_${NNN}`.
   - Двусторонняя подстановка в диагностических логах и текстах отчётов.

4. **Секреты, ключи API, токены, пароли (§22.1):**
   - Шаблон замены: `__BB_REDACTED_SECRET_${NNN}__`.
   - **Строго односторонняя замена.**

### 4.2. Алгоритм защиты от Unmasking Oracle

```
[Выходной unified diff от публичной модели]
                  │
                  ▼
   ┌──────────────────────────────┐
   │ Построчный синтаксический    │
   │ разбор unified diff          │
   └──────────────┬───────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
[Строки контекста ' ']    [Строки добавлений '+']
        │                           │
        │                           ▼
        │               Содержит ли токен секрета
        │               __BB_REDACTED_SECRET_*__?
        │                    │              │
        │                   ДА             НЕТ
        │                    │              │
        │                    ▼              ▼
        │           ОТКАЗ СДАЧИ        Разрешена замена
        │           dlp-violation      только хостов и IP
        │                                   │
        ▼                                   ▼
Разрешена обратная               [Контролируемый патч]
подстановка секрета                         │
для сходимости git apply                    ▼
        │                        Применение git apply
        └─────────────┬─────────────────────┘
                      │
                      ▼
        ┌───────────────────────────┐
        │  Вторичный DLP-скан       │
        │  результирующего коммита  │
        └─────────────┬─────────────┘
                      │
            Прошёл проверку?
              │            │
             ДА           НЕТ ──► ОТКАЗ: коммит блокирован
              ▼
    Успешная фиксация
```

- Если строка с маркером `+` содержит токен `__BB_REDACTED_SECRET_NNN__`, операция сдачи отклоняется с кодом `dlp-violation: token exfiltration detected in diff addition`.
- Текстовый отчёт исполнителя проверяется на наличие токенов секретов; при их обнаружении они заменяются на необратимую заглушку `[REDACTED]` без восстановления исходного значения.

## 5. Матрица доверия (Capability & Trust Matrix)

### 5.1. Уровни доверия маршрутов

В конфигурации политики (`policy.ts`) каждый маршрут маршрутизации обязан определять атрибут `trust`:

```typescript
export type RouteTrustLevel = "trusted-local" | "trusted-cloud" | "public";

export interface PolicyRoute {
  name: string;
  preset: string;
  trust: RouteTrustLevel;
  delivery: "commit" | "text";
  tools: boolean;
  confidentialPathsAllowed: boolean;
}
```

1. **`trusted-local`:**
   - Доверенные локальные модели (vLLM, Ollama) в защищенном контуре.
   - Маскируются только мастер-ключи хоста `~/.bb/`. Исходный код проекта передаётся без купюр.
   - Полный доступ к `git worktree` и локальной сети сборки.

2. **`trusted-cloud`:**
   - Корпоративные облачные провайдеры с подтверждённым соглашением о Zero Data Retention (Anthropic API, OpenAI Enterprise, Vertex AI).
   - Разрешён доступ к файлам `confidentialPaths`. Выполняется базовый скраббинг production-секретов.
   - Исполнение в изолированном worktree; разрешён доступ к корпоративным прокси-серверам пакетов.

3. **`public`:**
   - Бесплатные модели, публичные провайдеры, веб-интерфейсы.
   - Полный строгий DLP-фильтр (RFC-маскирование хостов, IP, токенов).
   - Физическое исключение `confidentialPaths`.
   - Исполнение строго в Snapshot Sandbox на базе Bubblewrap с закрытой сетью (`--unshare-net`).

### 5.2. Правило Fail-Closed

1. Если задача помечена меткой/флагом `--privacy strict`, либо рабочий набор изменений затрагивает хотя бы один файл из перечня `confidentialPaths`:
   - Задача допускается к раздаче **СТРОГО** на маршруты уровней `trusted-local` или `trusted-cloud`.
   - Если все доступные доверенные маршруты исчерпали квоту, испытывают сбой сети или отключены, конвейер переводит задачу в статус `blocked` с ошибкой:
     `route-unavailable: задача затрагивает confidentialPaths или помечена --privacy strict, но доверенные маршруты недоступны; автоматический фоллбэк на public-маршруты запрещён политикой безопасности`.
2. Попытка принудительно делегировать такую задачу на публичный маршрут через CLI отклоняется на уровне валидации `runEnqueue` / `resolveTransition`.

## 6. Приёмочные сценарии (Верификация 5 блокеров аудита)

1. **Тест Б1 (Snapshot Sandbox):**
   - Запуск агента на публичном маршруте.
   - Попытка выполнить `git log --all`, `git reflog`, `git rev-list --objects`.
   - Ожидаемый результат: виден ровно один начальный коммит `sandbox root snapshot`. История родительского репозитория отсутствует.
2. **Тест Б2 (Физическое исключение `confidentialPaths`):**
   - Задача на публичном маршруте. В репозитории существует файл `src/auth/secret.ts` из `confidentialPaths`.
   - Попытка прочитать файл через `cat /workspace/src/auth/secret.ts`.
   - Ожидаемый результат: пустой файл (`/dev/null`) или `ENOENT`. Содержимое не утекает.
3. **Тест Б3 (Защита от Unmasking Oracle):**
   - Агент возвращает unified diff, где в добавленной строке `+` находится токен `__BB_REDACTED_SECRET_001__`.
   - Ожидаемый результат: оркестратор бракует сдачу с ошибкой `dlp-violation`. Секрет не подставляется в репозиторий.
4. **Тест Б4 (Изоляция Bubblewrap):**
   - Агент пытается запустить сетевое соединение `curl https://google.com` или прочитать `/etc/shadow`.
   - Ожидаемый результат: отказ сети `Network is unreachable`, отказ доступа к системным файлам хоста.
5. **Тест Б5 (Fail-Closed):**
   - Задача с `--privacy strict`. Провайдер `swe2` (trusted-cloud) отключен или исчерпал лимиты.
   - Попытка перехода.
   - Ожидаемый результат: автоматический переход в `blocked` без попытки раздачи на `argon`/`web-gemini`/`public`.
