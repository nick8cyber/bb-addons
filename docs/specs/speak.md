# speak — озвучка сообщений чата (Gemini TTS и голос браузера)

Статус: принято и реализовано. Плагин `plugins/bb-plugin-speak`.

## 1. Назначение

Плагин добавляет кнопку чтения вслух для каждого сообщения чата в интерфейсе BB:

- **Высококачественный синтез речи**: интеграция с Gemini TTS (основная `gemini-3.1-flash-tts-preview`, резервные `gemini-2.5-flash-preview-tts` и `gemini-2.5-pro-preview-tts`) через Google AI Studio или локальный прокси.
- **30 естественных многоязычных голосов**: Kore (по умолчанию), Aoede, Fenrir, Puck, Charon и др.
- **Бесшовный фолбэк**: при исчерпании квоты, сетевом сбое или отсутствии ключа воспроизведение переключается на встроенный голос браузера (`speechSynthesis`).
- **Модель-чейн с учетом суточных и минутных лимитов**: интеллектуальная обработка HTTP 429 с расчетом кулдауна (до полуночи по Pacific Time для суточных квот либо 90 секунд для минутных).
- **Интеллектуальный фильтр текста**: 15-этапный конвейер очистки Markdown от кода, таблиц, ссылок и эмодзи.
- **Плавающий плеер (Overlay Player)**: плавающая карточка управления с паузой, прогрессом чанков и переключением скорости (`0.75×`–`2×`) с сохранением тембра голоса через WSOLA.

## 2. Архитектура и модель синтеза

### 2.1. Безопасность ключей и изоляция
Синтез через Gemini выполняется строго на бэкенде плагина (`server.ts`):
- Параметр `geminiApiKey` объявлен с атрибутом `secret: true`. Секрет хранится в файле с правами `0600` вне базы данных `bb.db` и никогда не передается на сторону фронтенда.
- Возможно указание кастомного эндпоинта `baseUrl` (например, CLIProxyAPI `http://127.0.0.1:8318/v1beta`) для балансировки нагрузки между пулом ключей.
- Браузер передает на сервер только текст и номер чанка, получая в ответ сгенерированное аудио.

### 2.2. Детерминированный чанкинг (`src/chunk.ts`)
Сырое uncompressed PCM аудио 24 кГц весит ~3.5 КБ на один символ текста, а после добавления 44-байтного RIFF/WAV заголовка и кодирования в base64 объём составляет ~4.8 КБ base64 на символ входного текста. Передача длинного сообщения целиком создавала бы многосекундную задержку и передачу мегабайтов данных. Плагин разбивает текст на порции:
- **Чистая функция нарезки**: функция разбиения текста детерминирована и работает одинаково на сервере и клиенте без передачи координат границ.
- **Первый чанк**: уменьшен до `FIRST_CHUNK_CHARS = 100` символов для старта воспроизведения через ~1.2 секунды после клика.
- **Последующие чанки**: увеличены до `CHUNK_CHARS = 260` символов для минимизации числа сетевых запросов.
- **Иерархия границ**: пустые строки (параграфы `\n\n`) → знаки препинания предложений (`.!?…` с закрывающими кавычками) → переносы строк → границы слов.
- **Порог наполнения**: точка разреза выбирается только при заполнении бюджета как минимум на 50% (`MIN_FILL = 0.5`).
- **Максимальный объем**: `MAX_SPEAKABLE_CHARS = 20_000` символов.

### 2.3. Цепочка моделей и кулдауны квот (`src/model-chain.ts`)
- Список поддерживаемых моделей (`TTS_MODELS`):
  - Основная модель: `gemini-3.1-flash-tts-preview` (по умолчанию).
  - Резервная модель: `gemini-2.5-flash-preview-tts` (по умолчанию при исчерпании квоты «When spent»).
  - Дополнительная модель: `gemini-2.5-pro-preview-tts`.
- При получении HTTP 429 парсится тело ошибки:
  - Суточное исчерпание квоты (`quotaScope === "day"`) → модель помечается исчерпанной до следующей полуночи по Тихоокеанскому времени (00:00 Pacific Time, когда Google сбрасывает квоты). На бесплатном тарифе AI Studio квота моделей линейки 2.5 учитывается отдельно от 3.1, предоставляя свежий лимит.
  - Превышение минутного лимита запросов (`burst`) → кулдаун на время `retryDelay` из ответа либо на 90 секунд.
- Кулдауны кэшируются в KV-хранилище демона (`quota-cooldown:<model>`), предотвращая повторные холостые запросы от параллельных чанков.

### 2.4. Клиентский плеер (`src/player.ts`)
- Единый синглтон `player`, управляющий аудио-контекстом Web Audio API и синтезатором `window.speechSynthesis`.
- Параллельная конвейерная предзагрузка (Fetch-ahead):
  - При старте воспроизведения (`streamChunks`, T=0) сразу параллельно запрашиваются все начальные чанки вплоть до 5 штук (`Math.min(totalChunks, 5)`).
  - В цикле воспроизведения запускается упреждающий параллельный запрос следующих до 5 чанков (ahead от `index + 1` до `Math.min(totalChunks, index + 6)`).
  - Пока воспроизводится текущий чанк, последующие уже параллельно синтезируются на бэкенде и декодируются, гарантируя непрерывное воспроизведение без пауз (gapless playback).
  - При возникновении ошибки на первом чанке выполняется переключение на резерв (failover), при ошибке на поздних чанках воспроизведение обрывается (`cutShort`), а все запущенные упреждающие запросы очереди отменяются через AbortController.
- Регулировка скорости (`0.75×`, `1×`, `1.25×`, `1.5×`, `2×`) с сохранением естественного питча голоса через time-stretching (WSOLA), без эффекта неестественно высокого тона.
- Запоминание скорости в `localStorage`.
- Автоматическая разблокировка аудио на мобильных тач-устройствах при первом взаимодействии.

## 3. Фильтрация и подготовка текста (`src/speakable.ts`)

Перед отправкой в синтезатор исходный Markdown сообщения очищается 15-этапным конвейером:
1. Вырезание блоков кода (fenced и indented).
2. Удаление HTML-комментариев и блоков `<script>`/`<style>`.
3. Удаление сносок вида `[^1]`.
4. Удаление изображений `![alt](url)`.
5. Преобразование ссылок `[текст](url)` в `текст`, удаление автономных URL.
6. Вырезание Markdown-таблиц целиком (строки с разделителями `|`).
7. Простановка точек в заголовках (Setext и ATX `#`) для создания естественной паузы.
8. Удаление горизонтальных разделителей (`---`, `***`).
9. Очистка маркеров цитат (`>`) и списков (`-`, `*`, `1.`) с гарантированием концевой пунктуации на каждом элементе.
10. Удаление обратных кавычек инлайн-кода (при этом идентификаторы и имена файлов сохраняются для прочтения).
11. Удаление маркеров форматирования (`**`, `*`, `__`, `_`, `~~`) с учетом границ слов (не ломает переменные `snake_case`).
12. Вырезание HTML-тегов, замена `<br>` на перенос строки, декодирование сущностей (`&quot;`, `&mdash;`, `&laquo;` и т.д.).
13. Вырезание эмодзи и пиктограмм (чтобы исключить зачитывание названий символов синтезатором).
14. Нормализация пробелов и переносов строк.
15. Обрезка по границе предложений до лимита в 20 000 символов.

## 4. UI-интеграция и DOM-контракты

### 4.1. Действие сообщения (`messageAction`)
- Слот `app.slots.messageAction`:
  - Идентификатор: `speak`.
  - Заголовок: `Read aloud`.
  - Иконка: `Play` (в строке действий используется векторная иконка плагина `icons/speak.svg`).
  - Поддержка выделения: если пользователь выделил часть сообщения мышкой, озвучивается только выделенный фрагмент (`context.selectedText`).
  - Идемпотентность: повторный клик по кнопке на том же сообщении останавливает текущее воспроизведение.
  - Синхронизация состояния кнопки через атрибут `data-speak-state="generating|playing|paused"` на элементах `button`.

### 4.2. Плавающий оверлей плеера (`SpeakOverlay.ts`)
- Монтируется через контент-скрипт `speak-overlay`.
- Отображает плавающую панель с элементами управления и статусом:
  - Текущий статус: «Генерация речи…», «Воспроизведение» или «Пауза».
  - Имя используемого голоса (`state.voice`, по умолчанию «Gemini»; выставляется при синтезе через Gemini TTS).
  - Счетчик чанков (`• X/Y`, отображается при общем числе чанков > 1).
  - Кнопка воспроизведения/паузы (`bb-speak-btn-playpause`) и кнопка закрытия/отмены (`bb-speak-btn-close`).
  - Кнопка переключения скорости воспроизведения (`bb-speak-btn-speed`, циклический выбор `0.75×`, `1×`, `1.25×`, `1.5×`, `2×`).

### 4.3. Раздел настроек (`SpeakSection.tsx`)
- Слот `app.slots.settingsSection`:
  - Выбор голоса из 30 вариантов Gemini.
  - Выбор основной модели синтеза и резервной модели при исчерпании квоты («When spent»).
  - Переключатель включения фолбэка на браузер (`fallbackEnabled`) и ползунок скорости голоса браузера (`browserRate`).
  - Кнопка тестового синтеза («Test» / «Testing…») с использованием фиксированной фразы пробы «Проверка голоса: так это будет звучать вслух.» (`PROBE_TEXT`, `server.ts:41`).

## 5. Серверные методы, HTTP API, CLI и конфигурация

### 5.1. RPC-контракт (`contract`)
- `status`: текущая конфигурация, наличие сохраненного API-ключа, список доступных голосов и моделей.
- `savePrefs({ prefs })`: сохранение пользовательских настроек (голос, модели, скорость).
- `synthesize({ text, chunkIndex })`: синтез одного чанка текста. Возвращает аудио в base64 (`audio/wav`) с метаданными (голос, сработавшая модель, индекс чанка, общее число чанков) либо типизированный код ошибки (`not_configured`, `auth`, `rate_limited`, `request_failed`, `empty`, `too_long`).
- `probe({ voice, model })`: короткий синтез фиксированной фразы для предпрослушивания голоса в настройках.

### 5.2. Прямой HTTP-эндпоинт (`POST /synthesize`)
- Сервер регистрирует прямой маршрут `POST /synthesize` (через Hono).
- Принимает JSON по схеме `contract.synthesize.input` (`{ text: string, chunkIndex: number }`).
- Возвращает JSON-результат `contract.synthesize.output` (base64-аудио, голос, модель, счетчик чанков) либо код ошибки (400 при некорректном JSON или невалидной схеме).
- В отличие от RPC, HTTP-эндпоинт передает в синтезатор сигнал отмены `context.req.raw.signal` (Node abort signal), что позволяет немедленно прерывать сетевые запросы к Gemini TTS при отключении клиента (остановка воспроизведения пользователем, переключение чанка, закрытие вкладки).

### 5.3. Консольный интерфейс (CLI)
- Плагин регистрирует CLI-команду `bb speak status` (`bb.cli.register`):
  - Проверяет и отображает статус ключа API (`Gemini API key: configured` или `not set — add it in ...`; значение ключа маскируется и никогда не выводится в консоль).
  - Выводит текущий голос (`voice`).
  - Выводит основную модель (`model`) с отметкой о кулдауне при превышении квот (`(out of quota until ...)`).
  - Выводит резервную модель (`when spent`) или указание перехода на голос браузера.
  - Показывает состояние и скорость браузерного фолбэка (`browser voice fallback: on (rate X) / off`).
- Поддерживает флаги справки `help`, `--help`, `-h`.

### 5.4. Настройки плагина
- `geminiApiKey`: строка, `secret: true`. Ключ Google AI Studio.
- `baseUrl`: строка, эндпоинт API (по умолчанию `https://generativelanguage.googleapis.com/v1beta`).
- Пользовательские предпочтения хранятся в KV по ключу `prefs` (валидируются схемой `prefsSchema`).

## 6. Тесты, сборка и верификация

- **Сборка**: `bb plugin build` → `dist/app.js` и `dist/server.js`.
- **Типизация**: `tsc --noEmit`.
- **Тесты**:
  - `node --experimental-strip-types --test tests/*.test.ts` (10 файлов тестов в `tests/`):
    - `chunk.test.ts`: детерминированность разбиения, проверка первого чанка, нарезка по предложениям, корректность surrogate pairs UTF-16.
    - `speakable.test.ts`: 15-этапный конвейер очистки Markdown (`toSpeakable`), удаление таблиц, списков и кодовых блоков, эвристика определения языка (`detectLanguage`).
    - `model-chain.test.ts`: цепочка моделей синтеза, парсинг квотных ошибок 429, расчет времени кулдауна, переключение на резервную модель.
    - `player.test.ts`: жизненный цикл плеера без браузера (моки Audio/DOM/fetch), параллельная упреждающая предзагрузка чанков (fetch-ahead до 5 чанков вперед при T=0 и в цикле), воспроизведение строго по порядку, пауза/возобновление/остановка, abort signal для отмены упреждающих запросов при сбое или остановке, fallback на голос браузера (`speechSynthesis`).
    - `gemini-tts.test.ts`: HTTP-клиент к Gemini REST API (функция `synthesizeChunk`), передача ключа в query (`?key=`), упаковка сырого PCM в 44-байтный RIFF/WAVE заголовок безусловно без валидации кодеков, классификация кодов ошибок (`auth`, `rate_limited`, `request_failed`), маскирование ключа в текстах ошибок (`redact`), нейтральная обработка отмены (`caller abort`).
    - `server-abort.test.ts`: проверка прерывания серверного синтеза (сигнал отмены в `POST /synthesize`), отмена исходящего запроса к Google без перехода на fallback, кулдауна или предупреждений.
    - `overlay-escaping.test.ts`: безопасность HTML-рендеринга оверлея, экранирование динамических значений (голос, статус, скорость) для защиты от XSS-инъекций.
    - `overlay-lifecycle.test.ts`: жизненный цикл монтирования оверлея, регистрация и очистка слушателей плеера, предотвращение утечек подписчиков при перезагрузке плагина.
    - `audit-findings.test.ts`: регрессионные тесты находок аудита PLUG-34: F-1 (залипание спиннера оверлея в состоянии `generating` после браузерного фолбэка), F-2 (залипание stage в `playing` при оборванном чтении на позднем чанке), F-3 (сброс паузы при фоновой загрузке следующего чанка), F-4 (ошибка расчета кулдауна на 1 час в дни смены DST).
    - `audit-plug39.test.ts`: регрессионные тесты аудита PLUG-39 (возобновление воспроизведения после паузы, санитизация и маскирование URL-кодированных API-ключей).

## 7. Известные ограничения и граничные случаи

- **Ключи GCP Cloud TTS не поддерживаются**: плагин работает строго с Gemini TTS через AI Studio API (`generativelanguage.googleapis.com`), сервисные аккаунты и ключи Google Cloud Text-to-Speech API не совместимы.
- **Встроенные голоса браузера**: при переключении на фолбэк браузера качество и список доступных голосов зависят от операционной системы клиента и установленных в браузере синтезаторов речи.
