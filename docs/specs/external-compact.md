# Контракт

Штатный `compactFirst` в bb 0.49 шлёт `/compact` внутрь сессии провайдера — модель не выбрать (см. расследование: `compactThreadContext` → provider `/compact`, SDK-хука нет). На треде в ~500k токенов это съедает ту же цену полного прочтения на модели треда (~12% пятичасового лимита у Claude). Плагин делает то же сжатие снаружи: сериализованную историю читает и сводит бесплатная Gemini через AI Studio — дорогая модель не тратится на чтение старого контекста.

## Модель и доступ

- **Суммаризатор: `gemini-3.6-flash`** через AI Studio REST (`generativelanguage.googleapis.com`), окно ~1M — тред ~500k проходит за один запрос.
- Ключ — секретная настройка плагина `geminiApiKey` (та же связка, что `geminiKeys` у voice-stt/live-call; значения в ответах/логах не светить).
- Фолбэк при `429`/квоте — второй ключ из той же настройки (две строки, как у voice-stt).

## Поток

1. **Детект оффера**: плагин опрашивает `threads context usage` своих/активных тредов; оффер = `usage.compactionOfferAt` в прошлом (то же условие, что у ядра: `compactExpiredCache` + `promptCacheTtlMs` + ≥100k). Опрос — редкий интервал (≥60с) и только по тредам со статусом idle/errored.
2. **Экспорт**: `bb handoff export <threadId> --out <tmp>` → сериализованная история.
3. **Гейт по размеру**: `usedTokens` (или размер экспорта) vs ~800k безопасной границы. Больше — чанкование по `bb handoff export --up-to-seq <N>` и иерархический summary (summary чанков → сводный). Совсем не влезает — явный отказ с причиной, не молчаливый обрыв.
4. **Сжатие**: один REST-запрос на `gemini-3.6-flash` с промптом «сожми сессию агента для продолжения: цели, решения, состояние репо, открытые задачи, инструкции владельца» → summary.
5. **Продолжение**: новый тред в том же проекте и окружении, первое сообщение = summary + ссылка на исходный тред; исходный тред не удалять (архивация — по отдельной настройке, default off).
6. **UI**: действие в меню/командах треда «Compact via Gemini (free)» + бейдж-напоминание, когда у треда истёк кэш. Не автомат — решение владельца, как у штатного тоггла.

## Ограничения (явно)

- **Новый thread id** — in-place компакт в том же треде невозможен без правки ядра (`compactThreadContext`). Принимаем: bb-тред после компакта новый, ссылка на старый в первом сообщении.
- **Качество summary** на Flash ниже Opus — для критичных тредов штатный compact остаётся выбором владельца.
- **Секреты**: ключ жёстко в secret-настройке; экспорт истории уходит в Google AI Studio — только треды, где это допустимо (без секретов в истории — предупреждение в UI).
- Не пересечение со штатным оффером: плагин не подменяет `compactFirst`, а даёт параллельное действие; тоггл ядра остаётся.

## Проверка и выпуск

- Unit: парсер оффера, гейт по размеру, чанкование по seq, сборка промпта, обработка 429/403/400 (та же таблица ответов шлюзов).
- Живьём: тред >100k с истёкшим кэшем → действие → новый тред со summary, у исходного ничего не потеряно; повтор на ~500k-треде (один запрос) и на >1M (чанки).
- Откат: отключение плагина; настройки и треды не затрагиваются.
