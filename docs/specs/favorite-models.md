# favorite-models — избранные модели (звёзды, пин, быстрый выбор)

Статус: принято и реализовано (PLUG-362/369/382/385). Плагин `plugins/bb-plugin-favorite-models`.

## 1. Назначение

Даёт пользователю отметить модели звёздочкой в нативном пикере модели BB и быстро возвращаться к ним:

- звёзды в строках пикера модели (все режимы: короткий список, длинный, вкладки провайдеров, поиск, сабменю «More models» — включая десктопный портальный Radix-поповер, disabled-строки отображаются без действия);
- закреплённый блок «Избранные» поверх списка (клоны строк, оригиналы не двигаются);
- раздел настроек: список по провайдерам, ручное добавление, импорт/экспорт JSON, переключатель pin;
- CLI `bb favorites` (list/add/remove/clear/export/doctor).

## 2. Идентичность модели и провайдера

- Ключ избранного = подпись строки пикера `label · route` (полная, с маршрутом — различает одинаковые лейблы на разных маршрутах; записи без `· route` совместимы и применяются ко всем маршрутам).
- Провайдер канонизируется через `normalizeProviderId` (src/store.ts) одинаково на клиенте, сервере и CLI. Канон — реальный providerId из каталога (`acp-devin`, `acp-opencode`, `acp-antigravity`, `acp-web-gemini`, `agy`, `claude-code`, `pi`, `codex`, …). Подписи табов сопоставляются id через каталог провайдеров; «Google Antigravity», «ACP Web Gemini» и «Antigravity (agy)» — РАЗНЫЕ провайдеры, не схлопываются.
- Существующие ключи мигрируются под канон внутри loadOrMigrate (под тем же write-lock, что и записи).
- Триггер модели: `aria-label="Provider, model and reasoning"`; владение поповером — через `aria-controls` триггера. Строки — `…-opt-N` (id может отсутствовать при выключенном поиске и в portal-сабменю). Вкладки провайдеров — `div.border-b` + `button.border-b-2`; ToggleGroup/radiogroup/toolbar не являются вкладками. Всё сверено с бандлом BB 0.49.0.

## 3. Хранилище и синхронизация

- Один версионированный KV-ключ `favorites:store` {version, favorites: {provider:[keys]}, modelLabels}. Legacy-ключи `favorites:map`, `favorites:labels`, `favorites:config` мигрируются один раз при первом доступе под write-lock; legacy config удаляется только после успешного `experimental_set`.
- Все read-modify-write сериализуются `withStoreLock`/`writeQueue`; каждая успешная запись инкрементит `version`.
- Клиент держит `serverVersion` + `mutationCounter` + поколение синка: поздний снимок не откатывает свежие мутации.
- Живой синк: refetch по `visibilitychange`/focus + периодический интервал. Мутации при упавшем RPC стоят в очереди с повтором; при окончательном фейле — честный откат состояния + тост.
- `setFavorites` (импорт) требует `baseVersion`; при расхождении — конфликт 409, чужие правки не откатываются.
- Совместимость: сервер понимает устаревший `toggleFavorite` (маппинг на add/remove) минимум один релиз — старые вкладки не теряют записи.

## 4. DOM-поведение

- Звёзды инжектируются только в контейнеры реального пикера (model-search или `-opt-` id); portal-сабменю «More models» признаётся по `aria-controls` из owned-поповера и обогащается контекстом родительской строки (провайдер/модель).
- Пин — клонами строк в отдельной секции; клик по клону применяет модель через оригинальную строку; последняя снятая звезда убирает секцию; `restoreDom` при dispose откатывает все следы.
- Расширение ширины панели — только при наличии `[data-radix-popper-content-wrapper]` (мобильный drawer не расширяется).

## 5. Конфигурация

- `bb.settings` + `experimental_set`: `pinToTop` (закрепление). Изменения применяются без reload страницы. При фейле записи — честный откат UI.

## 6. CLI и doctor

- `bb favorites list/add/remove/clear/export` — по нормализованным ключам, честные exit-коды; export совместим с форматом импорта.
- `bb favorites doctor [--fix]` — диагностика: неизвестные провайдеры, записи без маршрута (восстановление по меткам), сироты-метки, `default:*`. С `--fix` чистит и нормализует.
- Известный предел: doctor не определяет чужие модели внутри валидной группы — удаление вручную `bb favorites remove`.
