# Дата и время сообщений в тредах

## 1. Запрос владельца

Заменить сторонний Message Timestamps собственным форком. Дата и время каждого сообщения пользователя и агента должны быть постоянно видны без наведения и открытия меню. Старый плагин отключается и удаляется после проверки замены.

## 2. Поведение

Плагин `thread-timestamps`, пакет `bb-plugin-thread-timestamps`, живёт в `plugins/bb-plugin-thread-timestamps`. Основа — bighitbiker3/bb-plugin-message-timestamps, commit `fc365a7dde2cc12eef9fdc952c810b9798df8784`; происхождение сохраняется в README.

Для каждой строки `conversation` с корректным `createdAt` показывается `DD.MM.YYYY HH:mm`, 24 часа, часовой пояс браузера. Пользовательские сообщения, ответы агента и входящие сообщения других агентов имеют одинаковое покрытие. Время берётся из timeline BB; время загрузки страницы не используется. Служебные события и вызовы инструментов не являются сообщениями и не получают метки.

Метка расположена рядом с собственным сообщением: справа у пользователя, слева у агента. Полная дата и часовой пояс доступны при наведении. Она читается в светлой и тёмной теме и на узком экране. Две открытые панели, новые сообщения и прокрутка истории поддерживаются.

## 3. Устройство и ограничения

Форк сохраняет модель upstream: типизированный RPC + frontend content script. Используются публичный SDK и стабильный `data-timeline-row-id`; CSS не зависит от классов панели скрытых кнопок. Идентификаторы тредов берутся из идентификаторов видимых строк, а не заголовков сайдбара.

RPC отдаёт только запрошенные идентификаторы сообщений, timestamp и роль. История читается страницами с ограниченным количеством страниц за вызов; курсор и найденные метки кешируются. Старые сообщения за пределами первой пачки страниц догружаются следующими вызовами. Кеш и входные массивы ограничены, одинаковые запросы разделяют выполняющееся чтение. Ошибка одного треда не лишает меток остальные.

Frontend запрашивает только недостающие метки. Уже найденные даты не запускают повторный RPC. Ошибки повторяются с задержкой, без бесконечного опроса неизвестных строк инструментов. Отключение удаляет только принадлежащие плагину атрибуты, слушатели и таймеры; незавершённые запросы отменяются.

## 5. Решение

Отдельный ID позволяет проверить замену, пока upstream установлен, и исключает будущую перезапись форка обновлением чужого пакета. Основная ветка bb-addons и чужие рабочие изменения не меняются: разработка и документный коммит идут в отдельном worktree.
