# Контракт

Владелец поручил ограничить высоту окна ввода сообщений (promptbox): весь блок — текст редактора, вложения и тулбар — занимает не более 1/3 рабочей области экрана, чтобы верхние ~2/3 оставались под диалог для чтения. Реализация в существующем compact-ui (плагин «места на экране»): сворачивание списков, скрытие навигации и прочие space-оптимизации уже живут там. Новый плагин не создавать; BB/core, тема и модели не меняются.

## Требования

1. **Кеп на всю форму** `form.group/promptbox`: высота ≤ ⌊(innerHeight − 96px) / 3⌋, где 96px — штатный chrome вне рабочей области (page header + status bar). Не относительная высота всего экрана, а именно рабочей области чата.
2. **Переполнение поглощает скролл-зона редактора** `div.overflow-y-auto:has(.ProseMirror)`: ей выставляется inline `max-height` = текущая высота − переполнение. Тулбар, строка вложений и кнопки никогда не обрезаются и не уезжают за пределы формы.
3. **Одно правило для desktop и mobile** без media-query: развёрнутый мобильный композер использует тот же DOM (`group/promptbox`), кеп считается от того же вьюпорта; свёрнутый мобильный инпут (~50px) под кеп не попадает и не трогается.
4. **Стабильность, без осцилляции**: решение о кепе принимается по `scrollHeight` (натуральной высоте контента), а не по текущей обрезанной высоте. Пока контент велик — кеп держится; когда текст удалён и форма вернулась бы под кеп сама — inline `max-height` снимается, редактор восстанавливает естественную высоту.
5. **Полы**: не бороться ниже штатного inline `min-height` редактора (~103px) — нижний предел 104px. Сверху остаётся штатный потолок BB 312px: наш кеп срабатывает только когда он меньше.
6. **CSS-фолбэк без `!important`**: статическое правило `max-height: min(312px, calc(33svh - 56px))` в `lib/sidebar-controls.ts` убирает гонку до монтирования JS; inline-стиль JS-капа его корректно перекрывает.
7. Поведение BB не меняется: отправка, расписание, вложения, model picker, focus/keyboard, очередь сообщений. При отсутствии известной разметки — fail-open, интерфейс остаётся штатным.

## Проверка и выпуск

- Unit: полный набор тестов compact-ui, typecheck, `bb plugin build` — зелёные (134 теста). jsdom без ResizeObserver — монтирование деградирует без исключения.
- Chromium живьём: desktop 1440×1050 и mobile 390×844 (развёрнутый композер), длинный текст ~80 строк и симулированный блок вложений ~90px. Измеренная высота формы = ровно 0.33 рабочей области в обоих вариантах, редактор скроллится внутри, тулбар виден.
- Откат: удаление content script `composer-cap` и CSS-правила; настройки плагина не затрагиваются.
