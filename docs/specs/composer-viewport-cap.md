# Контракт

Владелец поручил ограничить высоту окна ввода сообщений (promptbox): весь блок — текст редактора, вложения и тулбар — занимает не более 1/3 рабочей области экрана, чтобы верхние ~2/3 оставались под диалог для чтения. Реализация в существующем compact-ui (плагин «места на экране»): сворачивание списков, скрытие навигации и прочие space-оптимизации уже живут там. Новый плагин не создавать; BB/core, тема и модели не меняются.

## Требования

1. **Кеп на всю карточку** `[data-app-composer]` (в 0.49 композер — div, не `<form>`): высота ≤ ⌊(innerHeight − 96px) / 3⌋, где 96px — штатный chrome вне рабочей области (page header + status bar). Не относительная высота всего экрана, а именно рабочей области чата.
2. **Переполнение поглощает скролл-зона редактора**: ей выставляется inline `max-height` = текущая высота − переполнение. Селектор — `div.overflow-y-auto:has(.ProseMirror)`, а в BB 0.49, где этой обёртки нет, — первый предок `.ProseMirror` с computed `overflow-y: auto|scroll` (fallback — сам ProseMirror). Тулбар, строка вложений и кнопки никогда не обрезаются и не уезжают за пределы формы.
3. **Развёрнутая очередь сообщений — ровно min(N, 3) строки.** Скролл-зоне очереди `[data-queued-messages-scroll]` и её flex-обёртке `[data-queued-messages-scroll-frame]` выставляется inline `max-height` = измеренная высота первых min(N,3) строк `[data-queued-message-row]` с зазорами (bottom последней видимой − top первой): 1 сообщение — 1 строка, 2 — 2, 3 — 3, 4+ — 3 строки и внутренний скролл. Фрейм клампится тоже — иначе flex-элемент держит карточку раздутой с мёртвым местом. Правило применяется всегда, не только при переполнении кепа. Свёрнутая панель остаётся смонтированной с нулевой высотой — её стиль не трогаем. Панель ищется внутри карточки и в её родителе (приоритет — кандидатам внутри карточки, отсоединённые копии отбрасываются). Логика очереди не зависит от селектора редактора: в BB 0.49 `div.overflow-y-auto:has(.ProseMirror)` внутри карточки отсутствует — скролл редактора определяется по computed `overflow-y` вверх от `.ProseMirror` (fallback — сам ProseMirror).
   **Рост панели:** фрейм очереди — `flex-1` внутри `min-h-0` flex-секции, и реальная высота ему отрезается контент-бюджетом секции, поэтому одного `max-height` на скролл мало: если до желаемой высоты не хватает места, `min-height` выставляется **только собственной `<section>` очереди** = нужная высота фрейма + паддинги секции + измеренные высоты прочих детей секции (строка заголовка, нижний шеврон). Предки (grid, карточка) растут по контенту сами и `min-height` не получают никогда: у хост-grid `align-content` по умолчанию stretch — любой излишек внутри grid растягивает все auto-треки, и зафиксированный потолок grid раздувал пустым телом соседнюю карточку-баннер, оставляя в idle видимый «оборванный» зазор (доказано живым дампом: grid 319px при начинке 282px). Слак считается по реальным соседям ребёнка, а не «высота предка − ребёнок» — иначе уже применённый `min-height` сам себя подтверждал и никогда не отпускал. Записи идемпотентны: пишутся только изменённые значения, лишние снимаются при реальном перерасходе (гистерезис `delta < −8` — без него анимация раскрытия флаппила потолок каждый кадр); при свёртке панели (нулевая высота) все `min-height` снимаются полностью. Триггеры перемера: MutationObserver на childList и атрибуты `aria-hidden`/`inert`/`class` с дебаунсом — `style` сознательно не наблюдается: хост непрерывно переписывает inline-стили (виртуализация), наблюдение `style` мельничило enforce→layout до фриза страницы. При N ≤ 3 высота берётся из `scrollHeight` скролла (точная, с паддингами); при N > 3 — измеренный спан первых трёх строк. Сохранённый `min-height` секции пересчитывается к актуальному `want` на каждом проходе (а не только при `delta < −8`): завышенный грант от закрывшегося инлайн-редактора отпускает и при `delta ≈ 0` — `delta` считается от уже ограниченного скролла, а не от секции.
   **Режим инлайн-редактирования очереди:** пока в очереди смонтирован `[data-queued-message-inline-editor]`, все выданные этой очереди ограничения снимаются (`max-height` скролла и фрейма, `min-height` секции) — хост сам резервирует место под редактор, а плагинный грант завышал slack и оставлял мёртвую зону. Кроме того, на развёрнутой очереди (`высота скролла > 0`) сбрасывается устаревший хостовый inline `height` скролла/фрейма/секции — только когда пин превышает натуральную высоту соответствующего контента более чем на 8px. Натуральные высоты по элементам: скролл — `scrollHeight` его `<ul>` + `padY` самого скролла (хост даёт скроллу `pt-1 pb-3` = 16px — без члена честный пин читался бы устаревшим: 16px > порога 8px); фрейм — натуральная высота скролла целиком (включая `padY` скролла) + `padY` фрейма + измеренные высоты остальных детей фрейма; секция — натуральная высота фрейма + `padY` секции + измеренные высоты соседей фрейма внутри секции (без фрейма — натуральная высота скролла + `padY` секции + соседи скролла). Натуральная высота читается из `<ul>` скролла, не из `scrollHeight` скролла — у overflow-контейнера `scrollHeight ≥ clientHeight`, и растянутый пином скролл подтверждал бы собственную раздутость; при отсутствующем или нулевом `<ul>` честный замер недоступен и пин НЕ трогается (fail-open). Сбрасывается только непустой inline `style.height` px-формата (`parseFloat`); `auto`/`100%` не затрагиваются. Если сам `<ul>` растянут под пин — натуральная высота растёт вслед за пином и пин сохраняется (fail-safe; резерв хоста под редактор живёт в измеренных высотах соседних элементов секции и учитывается через них, а не добавкой к пину). Хост пинит секцию явной высотой (transition + сохранённый ресайз, подтверждено живым дампом), устаревший пин сам пересчётом растёт (замерено 344→585px) и даёт мёртвую зону под редактором; условие по натуральной высоте исключает цикл «хост пишет ↔ плагин стирает», корректный пин не трогается. Свёрнутая панель (`высота скролла = 0`) пин сохраняет — сброс развернул бы её.
4. **Одно правило для desktop и mobile** без media-query: развёрнутый мобильный композер использует тот же DOM (`group/promptbox`), кеп считается от того же вьюпорта; свёрнутый мобильный инпут (~50px) под кеп не попадает и не трогается.
5. **Стабильность, без осцилляции**: решение о кепе принимается по `scrollHeight` (натуральной высоте контента), а не по текущей обрезанной высоте. Пока контент велик — кеп держится; когда текст удалён и форма вернулась бы под кеп сама — inline `max-height` снимается, редактор восстанавливает естественную высоту.
6. **Полы**: не бороться ниже штатного inline `min-height` редактора (~103px) — нижний предел 104px; у очереди нет пола — показывается ровно min(N,3) строк. Сверху остаётся штатный потолок BB 312px: наш кеп срабатывает только когда он меньше.
7. **CSS-фолбэк без `!important`**: статическое правило `max-height: min(312px, calc(33svh - 56px))` на `[data-app-composer]` в `lib/sidebar-controls.ts` убирает гонку до монтирования JS; inline-стиль JS-капа его корректно перекрывает.
8. Поведение BB не меняется: отправка, расписание, вложения, model picker, focus/keyboard, очередь сообщений. Единственное касание хостового состояния — сброс устаревшего inline `height` панели очереди в режиме инлайн-редактирования и только когда пин больше контента на 8px+: pin хост ставит заново при своём обновлении (transition/ресайз пользователя восстанавливаются самим хостом), корректный пин не трогается. При отсутствии известной разметки — fail-open, интерфейс остаётся штатным.

## Проверка и выпуск

- Unit: полный набор тестов compact-ui, typecheck, `bb plugin build` — зелёные (147 тестов). jsdom без ResizeObserver — монтирование деградирует без исключения. Регрессии режима инлайн-редактирования: (a) грант секции от большой строки-редактора уменьшается до `want` после закрытия при `delta ≈ 0`; (b) при смонтированном редакторе все гранты очереди снимаются и восстанавливаются после размонтирования; (c) базовые регрессии очереди (grow-only-section, свёрнутая панель, разделители) продолжают проходить; (d) развёрнутая очередь с редактором и пином > натуральной+8 → пин снят, пин в пределах 8px → не тронут; (e) свёрнутая очередь с редактором → пин ~44px сохранён; (f) растянутый пином скролл (`scrollHeight = clientHeight`) — натуральная высота читается из `<ul>`, пин снимается; растянутый `<ul>` — пин сохраняется.
- Headless-приёмка (runbook `infra/ui-screenshots-runbook.md`, живой UI): инлайн-редактор очереди открыт, `data-cap-mounted` отвечает текущей версией, `sH` секции стабильна по контенту (замеры 274–315px), хостовый `style.height` отсутствует или равен натуральному, мёртвой зоны нет; свёрнутая панель держит pin 44px.
- Chromium живьём: desktop 1440×1050 и mobile 390×844 (развёрнутый композер), длинный текст ~80 строк и симулированный блок вложений ~90px. Измеренная высота формы = ровно 0.33 рабочей области в обоих вариантах, редактор скроллится внутри, тулбар виден.
- Откат: удаление content script `composer-cap` и CSS-правила; настройки плагина не затрагиваются.
