# Раскрытие чатов порциями

## 1. Объём и границы

Владелец одобрил реализацию 23.10.2026: первое раскрытие до десяти, затем по десять; «Меньше» убирает по десять. Меняем только установленный Sidebar Collapse (база 4c1b5af), не BB core, тему, провайдеры, лимиты или ещё не установленное скрытие navigation rail. Существующие настройки сохраняются без миграции. visibleThreads сейчас равен 3, но алгоритм поддерживает любое допустимое значение настройки.

## 2. Модель страниц

Лимит B берётся из visibleThreads с существующей нормализацией. B=0 означает все чаты, без пагинации. Для каждой группы project:<id> хранится отдельный временный бюджет обычных корневых чатов: исходно B, после первого «Ещё» — ближайшее кратное 10 строго выше B, далее плюс 10. При B=3 последовательность 3 → 10 → 20 → 30; при B=10 — 10 → 20; при B=12 — 12 → 20 → 30.

«Меньше» возвращает предыдущий бюджет: при B=3 это 30 → 20 → 10 → 3. Последняя неполная порция не портит обратный шаг: для 27 обычных корней бюджеты 3 → 10 → 20 → 30 показывают 3 → 10 → 20 → 27; назад — 20. Не хранить 27 как бюджет вместо 30.

Если список сократился, «Меньше» выбирает наибольший шаг последовательности строго ниже min(бюджет, текущее число обычных корней), но не ниже B. Например, бюджет 30 и оставшиеся 12 корней → сразу 10; при числе корней ≤ B → B. Холостых промежуточных нажатий 30→20 при видимых 12 не делать.

Группы независимы. Сворачивание заголовка проекта и возврат сохраняют его бюджет в текущем монтировании. Перезагрузка страницы / повторное монтирование слота возвращает исходный бюджет, как старое состояние expandedGroupKeys. Смена B сбрасывает бюджеты к новому B без промежуточного кадра со старой картой: хранить B вместе с картой и игнорировать карту при несовпадении. Очистка исчезнувших проектов — только при status === "ready" по id из projects, не по производным groups. Loading/error и временно пустой threads при существующем проекте бюджет не сбрасывают.

## 3. Что считается чатом

Сохранить текущий порядок (закреплённые, опциональный unreadFirst, актуальность), исключение архивных, навигацию, меню, shortcut-атрибуты, вложенность, DnD проектов и native fallback. Скрытые служебные треды фильтрует хост; не добавлять новый фильтр по originPluginId или иным эвристикам.

Порция считает только обычные корневые чаты; pinned, текущий корень/предки текущего треда и attention при keepAttention всегда видны и бюджет не расходуют. Дети показываются с родителем и не считаются отдельной порцией. Поэтому строк может быть больше десяти. Повтор «Ещё» никогда не скрывает уже показанное при неизменном входе. Realtime-обновления списка и смена activeThreadId не сбрасывают бюджет.

## 4. Контролы

Внизу каждой открытой группы одна компактная строка с буквальными русскими текстами: «Ещё N» слева, «X из Y» в центре, «Меньше» справа. Plus/Minus — отдельные Icon с aria-hidden, а не читаемые текстовые глифы. Доступные имена: «Ещё N — <название проекта>», «Меньше — <название проекта>» (начинаются с видимого текста). Счётчик — обычный текст без live-region. X и Y — фактические показанные и все корневые чаты, включая защищённые; дети не входят. N — число действительно дополнительно открываемых обычных корней, не всегда 10 (первый шаг 3→10 даёт 7; остаток 20→27 даёт 7). Название «Ещё N» не обещает несуществующие строки.

«Ещё» доступно, только если остались скрытые корни. «Меньше» доступно при бюджете выше B, даже если после удаления чатов скрытых корней не осталось. Когда нечего раскрывать и бюджет исходный — всю строку не показывать. Если B=0, строка отсутствует.

Не добавлять отдельную третью кнопку «Свернуть всё». Кнопки — настоящие button type=button с понятным focus-visible и hit area минимум 28px высотой, не превышающей ширину узкой панели. Единая строка в светлой/тёмной теме, в PWA/mobile и desktop. У обеих кнопок aria-expanded отражает, что текущий бюджет выше B; кнопка складывания всего проекта сохраняет собственный независимый aria-expanded. При исчезновении нажатой кнопки фокус переводится на оставшуюся кнопку группы, иначе на fold-кнопку «Collapse <название проекта>». Переносить фокус только если исчезающая нажатая кнопка была document.activeElement; оставшимся кнопкам дать стабильные ключи. Не вызывать переход к чату или закрытие mobile drawer при пагинации.

Не делать scrollTo(0), scrollIntoView или автоматический переход к последней строке. Существующие чаты до границы сохраняют DOM-идентичность. Обычное ограничение scrollTop браузером при уменьшении высоты допустимо.
