# Usage Pro — переключатель биллинга Claude (подписка ↔ ключ Console)

## 1. Цель и наблюдения

В сайдбаре BB, в нижнем блоке лимитов (плагин `bb-plugin-usage-pro`, disclosure «Provider usage»), на вкладке Claude (`claude-code`) появляется переключатель биллинга Claude Code: подписка (OAuth) ↔ ключ Anthropic Console (`apiKeyHelper`). Владелец переключает одним кликом рядом с лимитами.

Инфраструктура на хосте уже есть и не изменяется:

- ключ лежит в `~/.claude/secrets/anthropic-console.env` (0600);
- `~/.claude/secrets/key-helper.sh` печатает ключ для `apiKeyHelper`;
- CLI `~/.local/bin/claude-key on|off|status` атомарно (через `jq` + tmp + rename) правит `~/.claude/settings.json`, перед правкой копирует файл в `settings.json.bak-claude-key`. `on` добавляет `apiKeyHelper` **и** `env.CLAUDE_CODE_PROMPT_CACHE_TTL="1h"` (на ключе дефолт кэша 5 минут — переменная выравнивает его до часа). `off` удаляет оба ключа, а опустевший объект `env` — целиком. Признак ON по-прежнему один — наличие `apiKeyHelper`.

## 2. Контракт

### Состояние

- Источник правды — только `~/.claude/settings.json`: `ON` = присутствует ключ `apiKeyHelper`, `OFF` = отсутствует. Состояние читается из файла при каждом запросе, не кэшируется и не хранится в плагине.
- Значение `apiKeyHelper` (путь к хелперу) нигде не возвращается и не логируется — только факт наличия ключа.
- Файл отсутствует или не парсится → `enabled: false` + признак ошибки чтения.

### RPC

Два метода в контракте плагина `usage-pro`:

- `claudeKey.status` — вход `{}`, выход `{ enabled: boolean, settingsReadable: boolean }`.
- `claudeKey.set` — вход `{ enabled: boolean }`, выход `{ enabled: boolean }` — фактическое состояние после операции, перечитанное из файла.

Переключение выполняет существующий `~/.local/bin/claude-key` (execFile, без shell): логика правки одна, резервная копия `.bak-claude-key` сохраняется. Путь к settings.json настраиваемый: читается из `CLAUDE_KEY_SETTINGS` (дефолт `~/.claude/settings.json`) и пробрасывается скрипту тем же env — плагин и скрипт всегда правят один и тот же файл. В тестах и e2e подставляется временная копия файла; живой `~/.claude/settings.json` приёмкой не переключается (включение ключа заставляет активные треды переписывать кэш всего контекста по тарифам API). Параллельные `set` сериализуются; во время операции повторный вызов ждёт её или отклоняется — UI в это время держит disabled. Скрипт отсутствует или завершился ненулевым кодом → `set` возвращает ошибку **без stderr и stdout** (там может оказаться ключ) — в RPC-ответ и логи уходит только код отказа.

### UI

- Расположение: вкладка `claude-code` блока «Provider usage», отдельная строка под карточками аккаунтов.
- Подписи: OFF — «Подписка», ON — «Ключ Console ($ из кредитов орг.)».
- В ON переключатель визуально выделен (amber/warning), потому что тратятся деньги.
- Подсказка (`title` у строки): «Действует со следующего хода во всех тредах Claude Code; кэш тредов перезапишется на первом ходе; на ключе кэш 1h».
- Пока статус не прочитан или идёт переключение — контрол disabled.
- Свежесть: UI перечитывает `claudeKey.status` при монтировании вкладки, после каждого `set` и опросом раз в ~30 с, чтобы `claude-key on|off` из терминала отражался в UI без перезагрузки.
- Ошибка `set` в UI — короткое «Не удалось переключить», затем перечитывание статуса.
- Ни значение ключа, ни его префикс, ни содержимое env-файла не попадают в UI, логи или RPC-ответы.

## 3. Границы файлов

- `plugins/bb-plugin-usage-pro/claude-key.ts` — новый серверный модуль (контракт + хендлеры + DI для тестов).
- `plugins/bb-plugin-usage-pro/claude-key.test.ts` — тесты чтения состояния и сериализации set.
- `plugins/bb-plugin-usage-pro/server.ts` — регистрация модуля.
- `plugins/bb-plugin-usage-pro/app.bundle.js` — компонент `ClaudeKeyToggle` и слот на вкладке `claude-code`; правка минимальная, без переписывания бандла.
- `dist/provider-usage-base.js`, `credit-retry.ts`, сборщик квот, OAuth и credentials не трогаем.

## 4. Приёмка

| Сценарий | Результат |
|---|---|
| Статус при OFF и при ON | Совпадает с `claude-key status` и содержимым settings.json |
| Клик OFF→ON (временная копия через `CLAUDE_KEY_SETTINGS`) | В копии появляется `apiKeyHelper` **и** `env.CLAUDE_CODE_PROMPT_CACHE_TTL="1h"`, UI показывает ON-состояние |
| Клик ON→OFF (временная копия) | Оба ключа удалены, `env.CLAUDE_CODE_PROMPT_CACHE_TTL` отсутствует (пустой `env` снят целиком); `jq -S .` результата семантически равен исходной копии |
| Живой файл | **Только чтение:** UI показывает OFF, совпадающий с `claude-key status`; переключений на живом `settings.json` приёмка не делает |
| Посторонние ключи settings.json | Не изменены (jq трогает только `apiKeyHelper` и `env.CLAUDE_CODE_PROMPT_CACHE_TTL`) |
| RPC-ответы и логи | Нет значения хелпера, ключа и env-файла |
| Финал | Состояние OFF (подписка) |
