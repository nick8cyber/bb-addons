# Русификатор bb

Плагин переводит интерфейс bb на русский язык. Переписку, код, диффы и то, что
ты печатаешь, он не трогает.

```sh
bb plugin install ./bb-plugin-ru
```

Дальше ничего настраивать не нужно: перевод включается сразу. Кнопка-глобус в
подвале боковой панели переключает язык на месте, без перезагрузки окна.

## Почему это плагин, а не языковой пакет

У bb нет слоя i18n: строки зашиты в JSX, каталогов локалей нет. Поэтому перевод
работает как контент-скрипт — обходит текстовые узлы уже отрисованного
интерфейса и подменяет те, что **точно** совпали со словарём, а
MutationObserver догоняет всё, что React дорисовал позже.

Из этого следуют два свойства, которые стоит понимать заранее:

- **Словарь неполный и всегда будет.** Сейчас в нём 2337 строк: боковая панель,
  поле ввода, шапка и лента треда, все страницы настроек (включая горячие
  клавиши целиком), расширения, диалоги, правая панель, описания встроенных
  плагинов. Строку, которой в словаре нет, ты просто увидишь по-английски.
- **Новая версия bb приносит новые строки.** Обновление bb ничего не ломает,
  но часть подписей вернётся к английскому. Ниже — как это лечится за пять
  минут.

## Что плагин не переводит принципиально

Совпадение только точное и только вне защищённых поддеревьев:

| Область | Якорь в DOM |
|---|---|
| тела сообщений — и твои, и ответы агента | `[data-markdown-preview]`, `[data-message-column]` |
| диффы в ленте | `[data-timeline-file-diff]` |
| текст сообщений в очереди | `[data-queued-message-row]` |
| код и вывод команд | `pre`, `code`, `kbd`, `samp` |
| то, что ты печатаешь | `textarea`, `input`, `contenteditable` |
| упоминания `@` | `[data-prompt-mention]` |
| что угодно по твоему выбору | `[data-bb-ru-skip]` |

Ответ агента «Done» — это ответ агента, а не кнопка «Done». Проверено вживую:
текст сообщений в треде побайтово одинаков при включённом и выключенном
переводе.

Подсказки (`placeholder`, `aria-label`, `title`, `data-placeholder`) переводятся
и у полей ввода — это подписи интерфейса, а не данные. Само значение поля
остаётся неприкосновенным.

Исключение — внутренности редактора промпта (`.ProseMirror *`, `.tiptap *`).
Tiptap держит своё представление документа и на любую правку атрибута
перерисовывает узел обратно: замер в живом bb показал 120 мутаций в секунду в
бесконечном пинг-понге. Поэтому мы туда не лезем. Цена — серая подсказка
«Ask anything.» в пустом поле ввода остаётся английской; `aria-label` самого
редактора, который читает скринридер, переведён.

## Как дорастить словарь

Плагин умеет сам собирать строки, которые ему незнакомы.

```sh
bb plugin config ru set collectMissing true
bb plugin reload ru
# полистай bb, потом:
bb ru missing --limit 50
```

Копилка отбрасывает то, что ключом словаря быть не может: пути, kebab-case
идентификаторы, подписи со счётчиками (`Codex · 31% 5h`) и шаблоны с
подставленными именами. Остаётся рабочий список на перевод.

Дальше:

1. Добавь пары в `dict/core.json` (`{"en": "…", "ru": "…"}`).
2. `npm run dict` — соберёт `src/dictionary.ts`.
3. `npm run build && bb plugin reload ru`.

Терминология зафиксирована в [dict/GLOSSARY.md](dict/GLOSSARY.md) — thread →
тред, worktree → рабочее дерево и так далее. Держись его: разнобой в терминах
хуже английского оригинала.

Пустое значение `ru` — это осознанное «оставить английским». Так помечены
строки, смысл которых без контекста непонятен.

### Откуда взялся словарь

`dict/src/batch*.json` — строки, извлечённые из исходников bb (JSX-текст,
`placeholder`, `aria-label`, подписи в пропсах) и переведённые пакетно.
`dict/core.json` — выверенные вручную значения, они перекрывают пакеты.
Сборка склеивает всё это, раскодирует HTML-сущности (`Couldn&apos;t` → `Couldn't`,
иначе ключ никогда не совпадёт с DOM) и сортирует.

## Команды

```
bb ru stats               состояние сбора и размер копилки
bb ru missing [--limit N] непереведённые строки, самые частые первыми
bb ru clear               очистить копилку
```

## Разработка

```sh
npm install
npm test          # 64 теста: чистая логика, DOM в jsdom, бэкенд на харнессе SDK
npm run typecheck
npm run build
```

Устройство: `src/translate.ts` — чистые правила (что переводить, что не
трогать), `src/translator.ts` — работа с живым DOM и откат, `src/runtime.ts` —
общее состояние фронтенда, `server.ts` — копилка и CLI, `app.tsx` —
контент-скрипт, раздел настроек, кнопка переключения.

## Сколько переведено

Замер `node tools/coverage.mjs` по полному набору из 20 маршрутов (главная, все
16 разделов настроек, расширения, навыки, автоматизации — список в самом
скрипте):

```
ИТОГО узлов: EN 336, RU 917 → покрытие 73.2%
```

Цифра 73% занижена тем, что в остатке почти всё — не пропущенный перевод:

| Английских узлов | Что это |
|---|---|
| 272 | имена плагинов и продуктов: Agent Proxy, Dispatch, Codex, Claude Code, Advisor… В боковой панели настроек этот список повторяется на каждой из 20 страниц, отсюда и вес. Имена собственные не переводятся. |
| 25 | описания сторонних плагинов и навыков из каталога и реестра — данные, приходящие с сервера каталога, а не текст bb |
| 17 | динамика: даты, счётчики, «2m ago», адреса почты |
| 12 | обрывки фраз, разрезанных ссылкой (см. `dict/exclude.json`) — оставлены английскими осознанно |
| 10 | собственно непереведённое |

То есть **из переводимого текста bb переведено ~99%**; 10 оставшихся узлов — это
описания трёх сторонних плагинов и названия навыков.

Две оговорки, чтобы цифру можно было проверять, а не верить:

- считаются **узлы, а не различные строки**, поэтому длинная однообразная
  страница весит больше короткой: `/settings/keyboard` даёт 255 русских узлов из
  917. Смотри разбивку по маршрутам в выводе скрипта.
- на страницах каталога плагинов и реестра навыков доля английского выше (50%):
  там основной текст — присланные каталогом описания сторонних расширений.

## Известные ограничения

- Фраза, разрезанная ссылкой или inline-кодом на несколько текстовых узлов,
  переводится только по частям, а это даёт полуанглийскую строку в неверном
  падеже. Такие куски занесены в `dict/exclude.json` и остаются английскими
  целиком — это осознанный выбор в пользу читаемости. Тест
  `src/dictionary.test.ts` не даёт им вернуться в словарь при следующем
  пакетном переводе.
- Подписи, собранные из шаблона с подставленным именем («Fork *имя навыка*
  into a new bb skill»), словарём не покрываются никак.
- Перевод живёт в DOM, поэтому исчезает при перезагрузке окна на миг раньше,
  чем применяется снова.
- Подсказка в пустом поле ввода промпта остаётся английской — см. выше про
  Tiptap. Проверено, что при включённом плагине приложение не производит ни
  одной лишней мутации DOM в устоявшемся интерфейсе (замер на четырёх
  экранах: 0 против 0 с выключенным плагином).
