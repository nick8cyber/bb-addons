# Live Call — статус и передача работы

> [!IMPORTANT]
> Обновление 02.11 (вторая сессия): **плагин написан и проверен живьём**. Конвейер звонка работает на реальном Gemini Live API: синтезированная речь → WS /call → вызов инструмента → реальные данные BB голосом (~1–3 с после тул-колла) → тред звонка в автосозданном проекте «Звонки». Негативный тест записи пройден: подтверждение класса L отменено кнопкой — ничего не запущено. Независимая проверка субагентом agy: вердикт «РАБОТАЕТ», все пункты ОК, секретов в публичной ветке нет. Коммиты 5a7c443 (код), df1bf13 (живые фиксы). Ключи внесены в секретную настройку плагина на сервере (2 ключа AI Studio).

## Решения владельца (02.11.2026)

| Вопрос | Решение |
|---|---|
| Режим по умолчанию | ⚡ Обычный (`gemini-3.8-live`); 🧠 Extended — в один тап |
| Extended перестал отвечать | Спросить «перейти на Обычный?», модель без слова владельца не менять |
| Ключи | 2: основной и запасной, запасной — только при ошибке квоты |
| IP для Google | Только хост BB, браузер к Google не подключается |
| Что можно голосом | Чтение — сразу; сообщение, ответ агенту, стоп — после «да»; разрешение — после «разрешаю»; запуск и раздача — только после «запускай» |
| Где хранить звонки | Отдельный проект BB «Звонки», один звонок — один тред (подтверждено владельцем 02.11) |
| Голос и язык | Algenib, русский |

- [x] Найдено и исправлено живьём (коммит df1bf13): у 3.8-live `speechConfig` живёт внутри `generationConfig` (в корне setup — 1007); кадры Gemini в рантайме bb-сервера приходят Blob/бинарными; `toolResponse` голосовой сессии — WHEN_IDLE (SILENT запрещает реагировать); приветствие только после setupComplete; финальный транскрипт копится кусками и финализируется по turnComplete; конец реплики владельца — 700 мс тишины; порядок «тред → say»; SDK-списки — голые массивы; алиасы snake_case в CallStore.
- [x] Независимая проверка субагентом agy (thr 02.11): «РАБОТАЕТ» — код по контракту, тесты 44/44, typecheck чистый, CLI и треды звонков корректны, ключей и IP в публичной ветке нет.
- [x] Треды звонков всегда прочитаны (владелец 02.11): markRead на thread.created/idle/failed + зачистка непрочитанных проекта «Звонки» при загрузке плагина. Проверено: свежий звонок остаётся «read».
- [x] Первый живой звонок владельца (02.11 18:53) показал дичь: модель сама запускала обзор до первого слова, read_thread падал циклом (list() не отдавал активный тред по id), в браузере AudioContext мог остаться suspended (тихий микрофон). Исправлено и проверено пробником: приветствие — одна фраза без инструментов; резолв треда через threads.get/listRunning; лимит 6 вызовов на ход с журналом tool_error; resume() обоим AudioContext. WS через Connect от браузера владельца работает (его звонки дошли до сервера).
- [x] Инцидент 02.11 19:27–19:34: диагностический патч сам убил микрофонный поток — Int16Array со смещением 5 байт бросал RangeError на каждом кадре; пик уровня теперь через DataView. Добавлена диагностика обеих сторон: сервер пишет в транскрипт звонка байты/пик микрофона за 5 с и предупреждает оверлей о тишине; браузер сообщает ошибки getUserMedia и 3 с тишины кадром client_log; оверлей явно пишет «микрофон молчит». У владельца кадры из браузера доходили, но были нулевыми — теперь это видно сразу.
- [x] Корень «мёртвого микрофона» владельца найден 02.11 19:41: AudioWorklet-децимация была навыворот — каждый входной сэмпл копировался ratio раз вместо прореживания, браузер отправлял 48 кГц-поток (1,45 МБ/5 с) с меткой 16 кГц, и Gemini получал голос, ускоренный в 3 раза. Исправлено: один выходной сэмпл на каждые ratio входных; серверный отчёт подтвердил норму 144 КБ/5 с. Уровень сигнала владельца при этом был громкий (пик 27225) — железо в порядке, вина целиком в коде.
- [x] Второй заход владельца (02.11 19:12) упёрся в квоту: close 1011 «Resource has been exhausted» не распознавался как квота → вечная петля «1008 session not found» с мёртвым ключом и старым handle, микрофон владельца капал в никуда. Исправлено: квота распознаётся (429/RESOURCE_EXHAUSTED/1011+/exhausted|quota/i) → переход на запасной ключ с пересказом; 1008 — переподключение без handle, при повторе смена ключа; backoff 1–10 с со сбросом на успешном ходе; приветствие один раз за звонок. Известный шум: спайк-тред генерирует «no active turn to interrupt» в серверном логе раз в секунду — это внутренняя механика bb по удалённому треду, не плагин.
