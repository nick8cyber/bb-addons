## Спайк «звонок = тред BB» (`spike-provider/`)

Минимальный провайдер. Мост не вызывает модель, а только отображает звонок: держит ход открытым и выводит реплики, которые присылает сервер плагина. Перед установкой задайте `LIVE_CALL_SPIKE_PROJECT` и `LIVE_CALL_SPIKE_ENV`. Сборка: `bb plugin build .`, сценарий: `bb live-call-spike demo [секунды]`.

Что показал (BB 0.48.1, SDK рантайма 0.6.104):

- ✅ Первая фраза — `prompt` в `threads.spawn`, следующие — `threads.send({ mode: "start" })`, реплики агента — `agentMessage`. Транскрипт нативный.
- ✅ Канал сервер → мост: у моста нет переменных `BB_*`, но есть общая папка `plugins/<id>/bridge-data`. Сервер пишет туда `server.json` с `bb.server.loopbackBaseUrl`, мост подключается по WebSocket к маршруту плагина (`auth: "local"`). Процессов моста несколько, поэтому мост сообщает, какой тред его, и сервер шлёт реплики только ему.
- ✅ Ход, открытый 121 с, закрывается чисто. Архивирование треда приходит как `thread/stop interrupt`.
- ✅ `experimental_visibility: "installed"` + `maintenance.health` + `provider/health → not_installed` прячет провайдер из выбора агентов, а `spawn` и `send` из плагина работают.
- ⚠️ `grammarVersions` нужен из ≥2 элементов. У `item.close` обязателен `status`. Неверная пачка событий отбрасывается **молча** — проверяйте каждую `threadDeltaSchema` из SDK.
