# e2e — живые проверки звонка в настоящем Chromium

Headless Chromium (Playwright) открывает BB, подменяет микрофон синтезированной фразой и звонит кнопкой телефона в футере сайдбара. Проверка — снаружи, по `bb call transcript <callId>` и логу плагина. Ключ AI Studio для синтеза — `K=<ключ>`, путь к браузеру — `EXE=<chrome-headless-shell>`. Результаты пишутся в `./out/`.

| Скрипт | Что проверяет |
|---|---|
| `shot.mjs` | скриншот BB (`URL`, `W`, `H`, `EVAL`) |
| `speech-e2e.mjs` | фраза `P` голосом → транскрипт, карточки, переход «Открыть», итог |
| `c-e2e.mjs` | несколько фраз через паузу (`P="a|b|c"`, `GAP`): подтверждение запуска «да» → подсказка, «отмена» → отмена |
| `x-e2e.mjs` | то же в Extended (`EXT=1`, `DELAY`) |
| `d-e2e.mjs` | старт в Extended и переключение на «Быстрый» |
| `m-e2e.mjs` | телефонная ширина (`W=390 H=844`) |
| `r-e2e.mjs` | обрыв WebSocket посреди звонка → возврат в тот же звонок |
| `reload-e2e.mjs` | закрыть страницу и открыть новую → тот же звонок |
| `rl-e2e.mjs` | `bb plugin reload` посреди звонка → новый звонок без падения (не запускать, пока звонит владелец) |
| `ext-prompt-ab.mjs` | A/B двух системных инструкций Extended на «системную ошибку» |
| `voicecmp.mjs` | высота голоса у разных моделей и голосов |
| `keycheck.mjs` | живы ли ключи плагина (`F=<файл ключей>`) |

Перед любым `bb plugin reload` — `bb call status`: перезагрузка рвёт идущий звонок.

> [!WARNING]
> Прямые прогоны к Gemini (`ext-prompt-ab.mjs`, `keycheck.mjs`) — только на ключах пула, не на ключах из секретов плагина. Иначе тест отнимает квоту у живого звонка. Перед прогоном — `bb call status`.

## `voice-e2e.mjs` — приёмка живым голосом (без ключа Gemini)

Основная обвязка приёмки подтверждения. Фразы владельца — готовые PCM-фикстуры 24 кГц (синтезирует куратор, в репозиторий не кладутся), подаются в подменённый микрофон **по событиям журнала звонка** (`confirm`, `question_heard`, `confirm_phase`), а не по таймеру. PASS/FAIL считается из журнала звонка в SQLite плагина.

```bash
bb call status | grep -q "звонок: нет" && \
EXE=<chrome-headless-shell> FIX=<папка фикстур> OUT=./out SCENARIO=<сценарий> [THREAD_ID=<тестовый тред>] [ECHO=0.6] \
timeout 240 node research/e2e/voice-e2e.mjs
```

Фикстуры: `send_ok` (просьба отправить сообщение в тред), `send_echo`, `da`, `otmena`, `q_projects`, `ask_last`, `brain_fail`.

| Сценарий | Тред | Что доказывает |
|---|---|---|
| `general` | нет | обычный звонок: фраза распознана, ответ по данным инструмента, «Завершить» ≤ 3 с (`W=390 H=844` — телефонная ширина) |
| `barge` | да | «да» через 150 мс после `question_heard` (вопрос уже звучит) засчитано как перебивание: `verdict.via = "barge"` (§7.1 п. 8) |
| `early` | да | «да» во время филлера (браузер проиграл ≥ 200 мс ответа, вопрос ещё не начался) не засчитано, сервер вставил «это не подтверждение», модель переспросила, «да» после вопроса — одно исполнение |
| `echo` | да | всё, что играет динамик, подмешивается в микрофон (`ECHO`); эхо не подтверждает действие; «Отмена» владельца после вопроса — `cancelled` |
| `fail` | да | неудача задания мозговому центру: голос честно говорит «не удалось», без «готово» |
| `button-early` | да | кнопка «Подтвердить» раньше вопроса: голос не перечитывает решённый вопрос |
| `open` | да | звонок по треду: без вопроса — пересказ ответа агента на последний запрос владельца |

Правила:
- каждый сценарий — минимум 2 прогона, расходятся — третий; сценарии строго по одному;
- критерии PASS в обвязке не ослаблять; правка обвязки — только при её собственной ошибке и с описанием в отчёте;
- тестовый тред — скрытый, с выдуманным содержимым, по окончании архивируется;
- `echo` при `ECHO=0.6` без AEC: модель может зациклиться на своём эхе, тогда pending истекает по TTL без ложных вердиктов — известный открытый вопрос (TODO).

Последние результаты (05.11, сборка с PLUG-119/117/120): early 2/2, barge 2/2, general 2/2, button-early 2/2, open 2/2 — PASS.
