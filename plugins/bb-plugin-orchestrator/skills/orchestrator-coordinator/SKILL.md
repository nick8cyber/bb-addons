# Координатор раздачи

Сам работу не выполняешь: декомпозируешь, раздаёшь, проверяешь, сводишь. Уровни и маршруты смотри в `bb orchestrator instructions` — в тексте навыка их нет.

## Порядок

1. **План — не команда.** Обсуждение и «учесть в плане» — не запуск: исполнителей раздаёшь только по прямому слову пользователя на этот шаг.
2. **Спека до раздачи.** Каждая задача исполнителю — по готовой спеке: в описании задачи пути, что сделать, чем проверить, отчётный контракт (ветка, SHA, проверки, статус). Расхождение кода со спекой — вопрос тебе, не исполнителю.
3. **Выбор уровня.** По описаниям из `bb orchestrator instructions`: сомневаешься — бери выше; сложное не понижай до слабого маршрута.
4. **Раздача — только через `delegate`** (инструмент `orchestrator_delegate` или `bb orchestrator delegate <KEY> --level <уровень>`). Не раздавай вручную (`bb tasks dispatch`, `bb thread spawn`) — так исполнитель теряет привязку, сторожа и отчёт.
5. **Не жди в форграунде.** После раздачи заканчивай ход — итог исполнителя придёт одним сообщением `[orchestrator]` от плагина (исход, ветка, sha7, чистота копии, отчёт до 3000 символов). Статус смотри `bb orchestrator status` / `orchestrator_status`, отмена — `orchestrator_cancel`. Свои поллеры поверх сторожа не ставь: слежение — его работа.
6. **Исходы сторожа.** Сторож сообщает: зависание, квота, падение, запрос прав, таймаут. При `autoFallback` он сам перевыпускает на следующий маршрут цепочки; без него (и когда цепочка кончилась) перевыпуск — твоё решение. Запросы прав исполнителей решаешь ты: `bb thread interactions list|approve|deny|grant|answer|respond <тред>` — не перекладывай на пользователя.
7. **Доработка — новый `delegate`.** Замечания и продолжение — новой раздачей той же задачи, а не сообщением старому треду: плагин сам передаст исполнителю раздел «Заход N» с коммитом прошлого захода (`--from <sha|ветка>` — своя точка, `--fresh` — начать заново). Ветку и рабочую копию исполнителя не открывай в других копиях — итог захода снимает плагин, чужие заходы трогать нельзя.
8. **Ревью до и после.** Разово раздай проверку на уровне `review`: спеки и план до раздачи, результат исполнителей после. На исполнение — только после «ОК» ревьюера (или исправления его замечаний).
9. **Проверка результата — сам.** Прогоняешь проверки из задачи, смотришь diff; потом — ревьюер на уровне `review`.
10. **Вливание итога — `bb orchestrator merge <KEY>`** (инструмент `orchestrator_merge`). После твоей проверки вливает итог захода в твою копию; конфликт возвращает копию в чистое состояние и при включённом `mergeAutofix` разбирает сам исполнитель новым заходом — повторный `merge` после его `done` пройдёт чисто. В защищённые ветки (main/master/dev) merge не вливает — туда только `release`.
11. **Push и PR — только ты.** Исполнители не пушат и не открывают PR; сведение, push и PR — после твоей проверки, сверки с базовой веткой и ревью.
